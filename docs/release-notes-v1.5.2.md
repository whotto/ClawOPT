# v1.5.2 —— 访问变快，团队上下文收口，两个删错东西的 bug

起因是一句「最近打开很慢」。查下来服务器本身 3ms 就回，慢在两头：
跨境链路每个新连接握手 0.6–3.5 秒，而我们把 3.4MB 未压缩的前端整包
每次发布都让用户重下一遍，还每 3 秒探测一次登录状态。

## 一、访问速度

- 后端加 gzip（SSE 流除外，压缩会把事件攒在缓冲区里）。原先 nginx 只按默认
  `gzip_types` 压 text/html，JS 和 JSON 全漏。
- 前端拆包：react / markdown / katex / i18n / motion / 图标各成独立 chunk，
  业务代码一改只重下业务那份（630KB）。文档预览模块（mammoth / xlsx / pdfjs，
  1.37MB）改为点开预览时才加载；代码高亮改按需加载语言包。
  首屏体积 3.4MB → 约 1.8MB，gzip 后约 520KB。
- 登录探测 3 秒 → 30 秒，切回标签页立即探测；所有轮询在标签页隐藏时暂停。
  团队 active-run 兜底轮询 500ms → 5s（SSE 才是主通道）。
- `group_messages(group_id, id)` 补索引：群消息所有读取都按这个过滤排序。

## 二、团队协作

- **重新生成绕过群锁**：正在输出时点重新生成会起第二个 run，旧 run 往已删除
  的消息 id 写 delta，前端据此复活一条幽灵消息。后端补 409，前端团队忙时禁用按钮。
- **上下文窗口**：历史窗口在「最多 15 条」之外加 9000 字预算；触发消息不再
  既在历史里又整段作为「最新任务」重复；「最新任务」加 6000 字上限，保头保尾。
- **链式转发设为 0 时成员仍 @ 了别人**：原先静默吞掉，现在出一条系统消息。

## 三、两个删错东西的 bug

- **v1.5.0 的清理删错了键。** 引擎文档里 `agents.list[].runtime` 是活的 ACP
  会话描述符（带 backend / mode），真正 legacy 的是 `agentRuntime`。
  原代码每次 provision 无条件删 `runtime`，用户手配的描述符会在任何一次
  重置或导入时静默消失。现在只删 v1.3 我们自己写的那种形状，并删 `agentRuntime`。
- **团队克隆体往源 Agent 工作区写空文件。** 克隆体复用源 Agent 的工作区，
  原先把「读不到 → ''」再写回去，源 Agent 缺哪个文件就凭空多一个空的同名文件。
  现在克隆体不改写工作区文件。
- 顺带：`systemPromptMode: agent` 的成员进团队后 SOUL/IDENTITY 全丢
  （系统提示按克隆体 id 推出的目录不存在），改按真实工作区路径读。
- 网关 2026.8 没有 `sessions.unsubscribe`，原先每次收尾刷一屏堆栈，现在记住一次。

## 没动但记下的

- 网关会话无限增长：每轮都发到同一个团队 session，从不压缩。提示词已把
  所需历史全部重放，可考虑每 N 轮自动换 epoch，需真机五处对账验证。
- 克隆体与源 Agent 共用 `memory/`，多个团队含同一 Agent 时并发读写同一目录。
- 外接 Agent 没有 CLI 装没装 / 登没登录的预检，失败文本会被当成正常回复。
