## 越界识别

### 2026-09-12 · 不在 ClawOPT 层重新规划 Agent 工作区

**提出的想法**：借鉴 OpenOPC 的做法，把「交付物」与「运行时状态」分开存放
（它的 `.opc/` 放运行时、`../OpenOPC_workplace/` 放产出，理由是防止运行时噪声污染工作区）。

**否掉的理由**：Agent 工作区是 `~/.openclaw/workspace-<id>/`——**那是 OpenClaw 引擎的地盘**。
OpenOPC 能这么做，是因为工作区本来就是它自己建的；ClawOPT 不是。在我们这层去重新规划
它的目录布局，等于越界管别人的运行时状态，而且会和引擎自己的约定打架。

这跟 v1.5.0 那次事故是**同一个错误的反向**：那次是把外部运行时写进了引擎不读的键
（管了不该管的），这次会是把引擎的东西按我们的想法重排（同样是管了不该管的）。

**边界**：ClawOPT 是协作平面，不是运行时。运行时状态的布局由引擎决定。

## 下一批候选（想清楚了，但没做）

### `externalMemberIdentityMismatch` —— 周期性身份自证

**是什么**：现在的身份校验只发生在接入时一次（`system/init` 事件里的 `model` /
`claude_code_version`）。候选做法是把它变成**周期性**的：每次运行都比对 init 事件报出来的
模型与版本，与成员配置里声明的是否一致，不一致就报一条不变量违反。

**理由**：外部 CLI 会自己升级，协议会漂移——**一次通过不等于一直通过**。这和
`cliBackendBinaryMissing` 是同一条判据的时间维度版本：那条问「二进制还在不在」，
这条问「它还是不是当初那个东西」。

本仓库已经为「一次通过不等于一直通过」付过代价：2026.8 升级当天握手身份就坏了，
而没人发消息所以没人发现（v1.5.1）。

**为什么没现在做**：`system/init` 的字段已经在 adapter 里抽出来了，但成员配置里还没有
「期望的模型/版本」这一格可比。等 UI 能配运行时之后一起做更自然。

**真机依据**：2026-09-12 端到端实测，`init` 事件确实带 `model=claude-sonnet-5`、
`claude_code_version=2.1.269`，字段可用。
