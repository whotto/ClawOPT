# v1.6.0 —— 出事时拿得到现场

这一版不加功能，只补一件一直缺的东西：**当某台机器上出问题时，我们能拿到什么。**

## 问题

这个产品装在用户自己的 Linux 主机上，我们看不见。翻一遍 CHANGELOG 就知道这有多要紧——
几乎每条修复都写着「生产实测」「真机上才看得见」「很可能从升级当天就坏了」：

- v1.5.1：整站聊天不可用，握手身份报错，**没人发消息所以没人发现**
- v1.2.6：判据少写一层路径，后果不是报错而是「判据永远不成立」
- v1.5.2：清理误删了用户手配的键

而此前能拿到的现场，只有 `index.ts` 里 91 处 `console.*`：没有请求号、没有结构化字段、
没有可导出的缓冲。排障要么让用户截图，要么要到 SSH。

## 三件事

### 1. `src/logger.ts` —— 结构化日志

条目带时间、级别、标签、正文、字段与可选的 `requestId`，落进一个 500 条的环形缓冲。
控制台输出**沿用既有的 `[Tag] 正文` 形态**，和仓库里那 91 处 `console.*` 混排时读起来一致。

两个刻意的选择：

- **脱敏发生在进缓冲区之前，不是导出时才洗。** 导出时洗意味着凭据在进程内存里以明文
  躺着，任何绕过导出口的读取（core dump、日后新加的接口）都拿得到。洗在入口只需守一个点。
- **敏感键下整棵子树抹掉，不钻进去逐个挑。** `auth` / `credential` 这类键下面装的几乎
  一定是凭据，而「只抹认得出的叶子」会漏掉词表之外的字段名。这个缓冲区会从 HTTP 出去，
  宁可少看见，不可漏出去。

家目录一律换成 `~`；`Error` 只留类别与错误码，不留 message 原文（V8 有一类 JSON 报错
会把输入原文嵌进去——那正是 v1.2.3 的泄露路径）与 stack。

### 2. `src/diagnostics.ts` + `GET /api/diagnostics` —— 一键取回现场

一份 JSON：应用版本、引擎版本、名册形状与每个 Agent 的 id/工作区、网关连通性、
浏览器预热状态、运行环境、最近 120 条日志。

三条纪律都是从既有事故里搬的：

- **读不到 ≠ 没有。** 引擎探不到报 `null` + 原因，不猜一个具体版本（`openclaw-version.ts`
  为这条写过整整一批用例）；配置读不动标 `configReadFailed`，而不是报告一个
  「0 个 Agent」的假象（v1.2.4 修的就是这个）。
- **任何一块采集失败都不牵连其余。** 排障工具在故障现场崩掉等于没有。
- **返回前整份再过一道脱敏。** 上面每一块都已经小心过了，但「小心」不是机制，那一行才是。

接口**默认受登录保护**——没有进 `AUTH_PUBLIC_PATHS`，它带着运行现场，不该匿名可取。

### 3. 设置 → 关于：一键复制

按钮把报告复制成可直接粘贴的 JSON。

注意一个容易漏的点：**ClawOPT 常以 http 跑在内网 IP 上，而 `navigator.clipboard` 要求
安全上下文，在那种部署下它根本不存在。** 所以留了一条不依赖它的退路，否则这个按钮
会在最需要它的那批机器上静默失效。三语文案齐备。

## 前端第一次有了测试

`test:frontend` 的实现一直是 `tsc`，全项目 **0 个前端用例**。而最容易无声回归的逻辑
正好都在前端：流式增量、历史对账、重连补拉三条路反复写同一条消息，写错的后果不是
异常，是用户眼看着已经出来的回答被更短的旧文本盖回去。

后端为同一条红线做了 `text-snapshot-protection.ts` 并配了用例，前端一条没有——
`AGENTS.md` 反对的「同一条判据两处分家」，这里就是一处。

- 新增 `src/utils/message-merge.ts`：用脚本从 `UnifiedChatView.tsx` **逐字节搬出，
  一个字符未改**（手抄副本迟早和原件分家）。组件 4,224 → 4,033 行。搬出来的唯一理由
  是测得动：原地 import 会把 react-markdown / katex / pdfjs 整条依赖链拖进测试进程。
- 21 条用例，`test:frontend` 改为 `tsc && vitest run`。

## 守卫与两次红证

- 注入「新内容更短仍采用」的回退缺陷 → 前端**四层同时红**（判据、合并、补丁合并、
  整批对账）；还原后 21/21 绿且文件逐字节一致。
- 注入脱敏旁路 → logger 2 条红。
- **第一次给 diagnostics 做红证失败了**：去掉最后那道脱敏闸门，9 条用例仍然全绿，
  说明它不承重——工作区路径压根没进报告（只取了 `count`）。这是「断言弱于标题」，
  本仓库在 `fs-call-sites` 与 `config-atomic-write` 上各栽过一次。
  修法不是删用例，是让报告真的带上 `roster.entries`（排障时「引擎看不看得见这个
  Agent」「它的工作区在哪」本来就是最常问的两件事，v1.2.5 那次事故就是这个）。
  闸门于是承重，再注入 → 1 条红。报告也因此更有用。

后端用例 212 → 234，前端 0 → 21。
