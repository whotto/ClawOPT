# v1.2.6 —— 会话库路径按真机校准

v1.2.5 里那个「引擎升级后指标读不到时明确告知」的功能，**在真机上从来没生效过**。

## 出了什么事

判据写的是「`agents/<id>/openclaw-agent.sqlite` 存在 → 引擎已升级」。
2026-09-03 在一台真的升到 OpenClaw 2026.8.2 的机器上量了一遍，实际是：

```
agents/<id>/
├── agent/openclaw-agent.sqlite        ← 会话库在这里，**多一层 agent/**
├── sessions/skills-prompts/           ← sessions/ 还在，但没有 sessions.json
└── session-sqlite-import-archive/     ← 迁移把旧 jsonl 归档在这里
```

少写一层的后果**不是报错，是判据永远不成立**：升级之后界面照样一片空白，
而我们以为已经修好了。**「诚实降级」自己变得不诚实**，是这一类失败里最难发现的形状——
它没有任何症状，只是那个功能不存在。

## 为什么单元测试没抓住

因为**用例和实现共享同一个错误假设**：用例把假的 sqlite 也放在
`agents/<id>/` 下，于是它是绿的。

> 用例与实现由同一个人在同一个假设下写出来时，测试证明的是「代码符合我的假设」，
> 不是「代码符合现实」。只有真机能推翻假设。

这一版补了一组**照搬真机目录形状**的回归用例，并且把归档目录也认作 2.x 的确证
（迁移完成但 sqlite 尚未建立时同样成立）。

## 验证

- `npm test`：**175 passed**（v1.2.5 为 172）
- 红证：把路径改回少一层，4 条用例变红——其中两条正是照搬真机形状的那组
