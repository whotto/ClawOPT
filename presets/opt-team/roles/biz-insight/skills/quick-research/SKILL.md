# 快速调研 · quick-research

> **够用就停。** 这个技能的核心能力不是搜得深，是**知道什么时候停下来回去干正事**。

## 硬约束

1. **上限 3 个数据点。** 到了就停，不管搜没搜完。
2. **搜完立刻回到主线**（需求分析或画布）。**不展开成调研报告。**
3. **每个数据点带来源 + 年份 + 可信度。**
4. **搜不到就说搜不到**，给替代渠道，不编不推。
5. **不给结论。** 交付数据，不交付"所以这个市场不错"。
6. **未满足本步退出条件，不得进入下一步。**

## 权限与数据边界

| 项 | 边界 |
|----|------|
| 读 | 联网公开信息；本工作区 `memory/` |
| 写 | `memory/YYYY-MM-DD.md`（数据点 + 来源） |
| 外发 | 无 |
| 敏感数据 | **不把搭档的项目名、合作方名、未公开构想打进搜索查询串**——查询串会离开本机 |
| 付费源 | 不用。需要付费数据 → 转情报调研并先问搭档 |
| 升权 | 不需要 `exec` |

## 何时使用 / 何时不用

| 场景 | 用不用 |
|------|--------|
| JTBD 推演中需要一个市场数字撑一下假设 | ✅ |
| 画布第 3 步想知道行业定价大概什么水平 | ✅ |
| "这个数字靠谱吗，帮我核一下" | ✅ |
| "帮我把这个赛道摸一遍" | ❌ → 情报调研 `oscar-research` |
| "这个数据我要引用到对外材料里" | ❌ → `point-intel`（需要饱和式搜索与交叉验证） |
| "帮我系统了解这个领域" | ❌ → CEO助理 `deep-research` |

**边界一句话**：**本技能服务于"当下这轮分析别卡住"，不服务于"把这件事搞清楚"。**

## 输入输出契约

**输入**：1-3 个具体的数据需求（从 JTBD 或画布过程中冒出来的）
**输出**：数据点清单（值 · 口径 · 年份 · 来源 · 可信度）+ 一句"回到刚才"
**上游**：`jtbd-demand` / `five-steps-quick` 中途冒出的数据缺口
**下游**：立刻回到调用它的那个技能，继续主线
**串联示例**：`five-steps-quick`(第3步卡住) → `quick-research` → `five-steps-quick`(继续第3步)

## 流程

### Step 1 · 锁定问题（≤3 个）

先把要搜的东西写成**可判真假的句子**，并确认数量。

```
✅ "我搜三个：① 这个品类 2025 年的线上均价带 ② 头部三家的会员定价 ③ 行业毛利率区间。够吗？"

❌ 直接开搜五六个方向
```

**退出条件**：数据点 ≤3 且每个可判真假。
**超过 3 个时**：说"这超出快速调研的范围了，要不要转系统调研？"

### Step 2 · 快搜

每个数据点：**2 轮关键词**（中英各一轮即可，不做饱和式），优先官方与行业报告。

**克制纪律**：

- 一个数据点搜不到 → **标"未找到"，继续下一个**。不死磕
- 找到多个打架的数字 → 全列出来标口径，**不做交叉验证**（那是 `point-intel` 的活）
- 顺手看到有意思但无关的东西 → **记进 `memory/` 备查，不在这轮展开**

**退出条件**：3 个点都有结果（找到 / 未找到），且总耗时 ≤5 分钟。

### Step 3 · 标注

| 数据点 | 值 | 口径 | 年份 | 来源 | 可信度 |
|--------|----|----|------|------|--------|

可信度用团队通用四级（见 `reference/credibility-standards.md`）：✅A / ⚠️B / ❓C / ❌D。

**快速调研的可信度上限是 ⚠️B**——因为没做交叉验证。**要 ✅A 必须走 `point-intel`。** 这条要显式告诉搭档。

**退出条件**：每个数据点四栏齐全，且已声明"本轮未做交叉验证，可信度上限 B"。

### Step 4 · 回到主线

```
✅ "三个数据：① 均价带 128-198 元（⚠️B｜行业报告 2025）
    ② 头部会员价 199/年（✅A｜官网）③ 毛利率没搜到，公开渠道拿不到，
    可以从上市同业财报倒推。
    **回到刚才第 3 步——付费方是企业还是个人？**"
```

**退出条件**：已给数据 + 已用一句话把话题拉回主线技能。

## 自检闸门

- [ ] 数据点 ≤3 个　→ 不过回 Step 1
- [ ] 每个点有值/口径/年份/来源/可信度　→ 不过回 Step 3
- [ ] 已声明"未做交叉验证，可信度上限 ⚠️B"　→ 不过，补上
- [ ] 未找到的已标注 + 给了替代渠道　→ 不过回 Step 2
- [ ] **最后一句把话题拉回了主线**　→ 不过回 Step 4
- [ ] 总耗时 ≤5 分钟　→ 超时说明该转系统调研
- [ ] 全文 0 处结论句式　→ 不过，改写
- [ ] 查询串里没有项目名/合作方名　→ 不过，立即向搭档报告

## 量化验收指标

| 指标 | 门槛 |
|------|------|
| 数据点数量 | ≤3 |
| 单点搜索轮次 | ≤2 轮 |
| 总耗时 | ≤5 分钟 |
| 四栏标注完整率 | 100% |
| 可信度上限声明 | 必有 |
| 未找到项的替代渠道覆盖率 | 100% |
| 拉回主线的收尾句 | 必有 |
| 结论句式出现次数 | **0** |

## 常见失败模式

| 失败 | 表现 | 怎么避免 |
|------|------|---------|
| **搜嗨了** | 一搜半小时，变成调研报告 | 3 个点 + 5 分钟是硬闸 |
| 死磕单点 | 一个数据搜八轮 | 搜不到就标未找到，往下走 |
| 忘了回主线 | 给完数据就没下文了 | 收尾句必须拉回 |
| 冒充 A 级 | 单一来源标成 ✅A | 快速调研上限 ⚠️B |
| 无口径 | 只给数字不说是什么口径 | 四栏缺一不可 |
| 越界给结论 | "看来这个价位有空间" | 只给数据 |
| 顺手展开 | 看到有意思的就多聊两句 | 记进 memory，不展开 |
| 泄密式检索 | 把项目代号打进搜索框 | 查询串脱敏 |

## 降级与失败路径

| 情况 | 做法 |
|------|------|
| **三个点都没搜到** | 如实说，给替代渠道，然后**照样回主线**："这三个公开渠道都拿不到，先按假设往下走，把它们记进待验证清单。" |
| **数据需求超过 3 个** | "这超出快速调研范围了。要不要先挑最关键的 3 个？剩下的等需要时转系统调研。" |
| **发现数据打架很严重** | 全列出来标口径差异，说明"这里分歧很大，要引用的话建议走 `point-intel` 做交叉验证" |
| **搭档要求把它扩成完整调研** | 说清区别："完整调研要走 OSCAR 八步，产出和耗时完全不同。要转吗？"——**转，而不是在这里悄悄扩** |
| **搜到的全是软文** | 标 ❓C 并说明"来源多为厂商内容"，建议去社区找真实反馈或走 `point-intel` |
| **数据会影响重大判断** | 提醒一句："这个数字如果要撑一个大决定，建议让情报调研做交叉验证——我这轮只有单源。" |

## 执行留痕与记忆写回

**留痕**：数据点连同来源与检索日期写进当天记录，下次同类问题可直接复用，不重复搜。

**写回 `memory/YYYY-MM-DD.md`**：搜了什么、为哪个分析服务、结果与来源、未找到的项。

**长期沉淀 `MEMORY.md`**：哪些数据源对搭档的行业最有用（下次直奔那里）、反复需要但一直搜不到的数据（→ 说明该建立自有数据采集）。

**技能记忆（L4）触发**：若某类数据（如某行业定价）有稳定的最佳来源，沉淀成候选技能或直接写进 `AGENTS.md` 的 Local notes。
