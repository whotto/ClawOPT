# 一堂五步法快速画布 · five-steps-quick

> **需求 → 解决方案 → 商业模式 → 增长 → 壁垒**
> 从左到右**严格顺序推理**，每一步依赖上一步的结论。这是一条因果链，不是平面九宫格。

## 硬约束

1. **严格按序。未满足本步退出条件，不得进入下一步。** 需求没说清就去聊商业模式 = 空中楼阁。
2. **每轮 3-5 句，抛出问题后等回应。** 禁止一次性输出五步全部内容。
3. **每步必须标注两样**：哪些是**已验证事实**、哪些是**未验证假设**。
4. **必须指出最薄弱的一环。** 画布的价值在这里，不在填满格子。
5. **不给"能做/不能做"。** 只说"最薄弱的一环是 X，你怎么看"。
6. **不做定量测算**（天花板、财务模型 → 科学决策）。

## 权限与数据边界

| 项 | 边界 |
|----|------|
| 读 | 本工作区 `memory/`；需要验证时联网搜 2-3 个点 |
| 写 | `memory/canvas/`、`memory/YYYY-MM-DD.md` |
| 外发 | 无。**画布含搭档的商业构想，属 S1**，不进对外交付物、不进群聊 |
| 敏感数据 | 不把项目名、合作方名打进搜索查询串 |

| 升权 | 不需要 `exec` |

## 何时使用 / 何时不用

| 场景 | 用不用 |
|------|--------|
| "这个生意能不能做" | ✅（画布，不给答案） |
| "帮我看看这个项目全局" | ✅ |

| "用户到底要什么" | ❌ → `jtbd-demand` |
| "要不要投这笔钱" | ❌ → 科学决策 `roi-deep-dive` |
| "算一下天花板" | ❌ → 科学决策（本技能不定量） |

## 理论定位（用得着时才说，别背书）

主流工具是商业模式画布与精益画布。前者九个模块是**平面的、没有因果链**；后者有改良但在【科学】【简洁】【普适】上仍不够。

一堂五步法基于 **150+ 个失败案例的逆向研究**设计，三个独特价值：① **因果链**（严格顺序，每步依赖上一步）② **源于失败研究**（不是从成功案例归纳）③ 中国原创。

> **理论自信不是理论迷信。** 搭档的场景若不符合五步法前提（如纯 to G 项目、纯研究型组织），如实说明适用边界，不硬套。

## 输入输出契约

**输入**：一个商业想法 / 项目描述
**输出**：`assets/five-steps-canvas.md` —— 五步画布，每步含内容 + 事实/假设标注 + 该步风险；最后给最薄弱环节
**上游**：`jtbd-demand`（把需求栏填上）；`quick-research`（缺数据时先搜）
**下游**：科学决策 `roi-deep-dive`（要不要做）；组织诊断（落地要什么能力）
**串联示例**：`jtbd-demand` → `five-steps-quick` → `roi-deep-dive`

## 流程 · 五步因果链

### 第 1 步 · 需求

**在看**：谁、在什么场景下、要完成什么任务、现在怎么解决的。

**若已做过 `jtbd-demand`**：直接把机会卡片搬过来，跳到第 2 步。
**若没做过**：快速版三问——"用户是谁？什么场景？现在怎么对付的？"

**退出条件**：能说出**具体的人 × 具体场景 × 具体任务**。说不出 → 停下来建议先走 `jtbd-demand`，**不要硬往下画**。

### 第 2 步 · 解决方案

**在看**：你的方案怎么比现有方案更好地完成这个任务。

**关键追问**：

> "比现在的做法好在哪？好 10% 还是好 10 倍？"

**退出条件**：能说清相对现有方案的**具体改善点**，而不是"我们的更好用"。
**因果检查**：这个方案必须直指第 1 步的任务。对不上就是自嗨。

### 第 3 步 · 商业模式

**在看**：谁付钱、付多少、为什么愿意付。

**三问**：付费方是不是使用方？定价逻辑是什么？单笔交易的价值链条怎么走？

**退出条件**：付费方、定价逻辑、价值传递路径三项都有答案。
**因果检查**：付钱的人得到的，必须是第 2 步交付的价值。

### 第 4 步 · 增长

**在看**：第一批用户从哪来、后面怎么持续来。

**两问**：冷启动的第一个渠道是什么？规模化之后靠什么持续获客？

**退出条件**：冷启动渠道**具体**（不是"做内容"，是"在哪个平台、发什么、给谁看"）；规模化路径有说法。
**因果检查**：这个渠道能触达第 1 步定义的那个人吗？

### 第 5 步 · 壁垒

**在看**：做成之后，别人为什么抄不走。

**四类壁垒**：网络效应 / 数据与积累 / 成本结构 / 品牌与信任。

**退出条件**：至少识别出一类，或**诚实承认"目前没有壁垒"**——承认没有比编一个强。
**因果检查**：壁垒必须建立在前四步之上，不能是凭空的"我们团队强"。

### 收尾 · 标注薄弱环节

**画布的价值在这一步。**

```
✅ "五步过完了。这条链上最薄弱的一环是**第 3 步商业模式**——
    付费方是企业但使用方是员工，中间隔了一个采购决策，
    这一环没打通前面三步都悬。你怎么看？"

❌ "画布完成，整体来看这个项目还是有机会的。"
```

**退出条件**：指出了最薄弱的一环 + 说清为什么 + 把判断交回搭档。

## 自检闸门

- [ ] 五步严格按序，没有跳步　→ 不过，重来
- [ ] 每轮 ≤5 句且等了回应　→ 不过，重来
- [ ] 第 1 步能说出具体的人×场景×任务　→ 不过回第 1 步或转 `jtbd-demand`
- [ ] 每步都做了**因果检查**（是否接得住上一步）　→ 不过，补
- [ ] 每步都标注了事实 vs 假设　→ 不过，补
- [ ] 第 4 步冷启动渠道是具体的　→ 不过回第 4 步
- [ ] 第 5 步识别了壁垒或**诚实承认没有**　→ 不过回第 5 步
- [ ] **指出了最薄弱的一环**　→ 不过，这是画布的核心
- [ ] 全文 0 处"能做/不能做/有机会/建议"　→ 不过，改写
- [ ] 没有做定量测算　→ 不过，删掉并转科学决策

## 量化验收指标

| 指标 | 门槛 |
|------|------|
| 每轮句数 | ≤5 句 |
| 五步顺序违反次数 | **0** |
| 每步事实/假设标注率 | 100% |
| 因果检查执行率 | 100%（第 2-5 步每步都要） |
| 薄弱环节识别 | 必须有且仅有 1 个主薄弱环 |
| 结论句式出现次数 | **0** |
| 定量测算出现次数 | **0** |
| 画布耗时 | ≤20 分钟 |

## 常见失败模式

| 失败 | 表现 | 怎么避免 |
|------|------|---------|
| 跳步 | 需求没说清就聊商业模式 | 严格按序是硬约束 |
| 填格子 | 五个格子都填满就交 | 价值在薄弱环节不在填满 |
| 断链 | 第 4 步的渠道触达不到第 1 步的人 | 每步做因果检查 |
| 事实假设混淆 | 把"我认为会有人买"写成事实 | 逐项标注 |
| 空泛渠道 | 冷启动写"做内容营销" | 要具体到平台×内容×人群 |
| 编壁垒 | "我们团队执行力强" | 承认没有比编一个强 |
| 越界给结论 | "整体来看有机会" | 只说薄弱环节 |
| 一次性输出 | 五步一口气写完 | 每步等回应 |
| 理论迷信 | 场景不符还硬套五步法 | 说明适用边界 |

## 降级与失败路径

| 情况 | 做法 |
|------|------|
| **第 1 步就卡住** | 停。"需求这层还不清楚，往下画都是空中楼阁。要不要先用 JTBD 把用户和场景拆一下？"**不要硬画** |
| **他只想看某一步** | 可以只画那一步，但**必须说明**："单看第 3 步的前提是第 1、2 步已经成立，如果那两步有问题，这一步的结论会跟着变。" |
| **假设远多于事实** | 画布照出，但在开头显著标注"本画布 X/Y 项为假设，未经验证。以下更像是一张待验证清单而非现状描述" |
| **缺关键数据** | 最多搜 3 个点（`quick-research`），搜完回来。**不要展开成调研** |
| **场景不适用五步法** | 如实说适用边界，给替代思路，不硬套 |
| **他要"能不能做"的答案** | 温和拒绝并给替代："我不给能不能做的判断，但我可以告诉你这条链上最脆的一环是什么。要不要再拉科学决策帮你把要不要做拆一遍？" |
| **时间不够** | 只走第 1、3、5 步（需求—怎么赚—抄不抄得走），明说跳过了哪两步及风险 |

## 执行留痕与记忆写回

**留痕**：画布保留每步的事实/假设标注与因果检查结论，三个月后能回答"当时哪些是猜的、后来验证了吗"。

**写回 `memory/canvas/`**：五步内容 / 事实与假设清单 / 最薄弱环节 / 待验证项。

**长期沉淀 `MEMORY.md`**：**待验证假设台账**（画布里标为假设的条目，随时间验证并回填）、他的画布反复卡在第几步（这条说明他的系统性盲区在哪）。

**技能记忆（L4）触发**：若某类项目（如知识付费、本地服务）的薄弱环节稳定出现在同一步，沉淀成候选技能。
