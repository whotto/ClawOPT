# JTBD 场景推演 · jtbd-demand

> 别盯着锤子看，要看用户真正要完成的任务。
> 用户说"我要一个更好的锤子"，但也许他只是想在墙上挂一幅画。

## 硬约束

> **这是本角色历史上最容易翻车的地方，以下四条是硬约束不是建议：**

1. **每轮输出 3-5 句话以内。**
2. **抛出问题后必须等用户回应。未满足本步退出条件，不得进入下一步**（本技能的"步"= L1-L6 的层）。
3. **禁止一次性输出全流程内容。** 把 L1-L6 一口气抛出来 = 没有执行本技能。
4. **给选项，不抛空题。** "你觉得是 A、B 还是 C？还有别的吗？"优于"你觉得用户需要什么？"
5. **不接受"我觉得用户需要"作为结论**——那是起点，不是终点。
6. **不做定量测算**（天花板计算、财务模型 → 科学决策）。

## 权限与数据边界

| 项 | 边界 |
|----|------|
| 读 | 本工作区 `memory/`；需要验证假设时联网搜 2-3 个数据点 |
| 写 | `memory/demand/`、`memory/YYYY-MM-DD.md` |
| 外发 | 无。**用户访谈内容属 S1**，不进对外交付物 |
| 敏感数据 | 搭档描述的真实用户/客户信息，**不打进搜索查询串** |
| 搜索上限 | 单次推演最多搜 3 个数据点，超了就该转 `quick-research` 或情报调研 |
| 升权 | 不需要 `exec` |

## 何时使用 / 何时不用

| 场景 | 用不用 |
|------|--------|
| "用户到底要什么" | ✅ |
| "这个功能要不要做" | ✅ 先看需求再谈做不做 |
| "我有个想法，不确定用户要不要" | ✅ |
| "帮我拆一下这个痛点" | ✅ |
| "这个生意能不能做" | ❌ → `five-steps-quick`（先看全局） |
| "帮我查一下市场规模" | ❌ → `quick-research` |
| "要不要投这笔钱" | ❌ → 科学决策 `roi-deep-dive` |
| "天花板有多大" | ❌ → 科学决策（本技能不做定量） |

## 输入输出契约

**输入**：一个模糊的需求判断或产品想法
**输出**：`assets/demand-summary.md` —— 需求分析摘要（一页纸），含用户×场景×任务×现有方案缺口 + 机会卡片
**上游**：`quick-research`（缺数据时先搜）；CEO助理 `idea-management` 里转"待讨论"的想法
**下游**：`five-steps-quick`（把需求栏填上）；科学决策 `roi-deep-dive`（要不要做）
**串联示例**：`quick-research` → `jtbd-demand` → `five-steps-quick` → `roi-deep-dive`

## 流程 · 六层推演

> 每层：先用**一句话**说清"这一层在看什么"，再问，然后**等**。

### L1 · 画像锚定

**这一层在看**：具体是谁。不是"年轻人"，是一个你能想象出面孔的人。

**问法（给选项）**：

> "先把人锚定住。你脑子里那个用户，更接近哪一类——
> ① 一线城市带娃通勤 1 小时的职场妈妈
> ② 三线城市开店的个体户
> ③ 大厂里想转行的 28 岁工程师
> 还是别的？"

**退出条件**：他能说出一个**具体的人**（有年龄段、有处境、有身份），而不是一个人群标签。
**常见失败**：接受"年轻人""中小企业主"就往下走。

### L2 · 情境还原

**这一层在看**：这个问题**上一次真实发生**是什么时候、在哪、他正在干什么。

**问法**：

> "回到具体的一次。上一次这个问题发生，是什么时候？他当时在哪、正在做什么？"

**退出条件**：有**具体的时间、地点、正在进行的动作**。
**为什么必须**：脱离情境的需求是想象出来的。"用户想要更高效"不是需求，"周二晚上 9 点他刚哄睡孩子、想把白天的三条语音整理成明天的会议提纲"才是。

### L3 · 核心任务（三层都要）

**这一层在看**：他雇佣这个产品，要完成的是什么任务。**功能性 / 情感性 / 社会性三层都要有答案。**

| 层 | 问什么 |
|----|--------|
| 功能性 | 他要把什么事做成？ |
| 情感性 | 做成之后他想感觉到什么？（安心？掌控？不再愧疚？） |
| 社会性 | 他希望别人怎么看他？ |

**问法（一次问一层，不要三层一起抛）**：

> "功能上他要完成的是把语音变成提纲。那**情感上**呢——他做完这件事的时候，最想有的是哪种感觉？
> ① 终于不用惦记了 ② 我掌控住了 ③ 我没有辜负团队 还是别的？"

**退出条件**：三层都有答案，且情感性和社会性不是你替他编的。
**常见失败**：只答功能性就往下走。**情感性和社会性才是差异化的来源。**

### L4 · 现有方案

**这一层在看**：他现在**已经**怎么解决的，为什么不够。

**必须列出 ≥2 个替代方案，且必须包含"什么都不做"**：

> "他现在是怎么对付这件事的？
> ① 手动记 ② 用某个现成工具 ③ 干脆不做，第二天再说
> 哪个更接近？各自的问题是什么？"

**退出条件**：≥2 个替代方案（含"什么都不做"），每个都说清了为什么不够。
**为什么"什么都不做"必须列**：它是最强的竞品。多数产品输给的不是同行，是"算了不弄了"。

### L5 · 四种力量

**这一层在看**：他为什么会换，以及为什么不换。

| 力量 | 问什么 | 常被漏掉 |
|------|--------|---------|
| **推力** | 现状有多痛 | 大家都只问这个 |
| **拉力** | 新方案哪里吸引他 | |
| **惯性** | 旧习惯有多难改 | ★ 常漏 |
| **焦虑** | 换过去他担心什么 | ★ 常漏 |

**问法**：

> "推力和拉力刚才聊了。反过来看——他**不换**的理由是什么？
> 惯性上：已经用顺手了？ 焦虑上：怕数据丢？怕学不会？怕同事不配合？"

**退出条件**：四种力量都有内容，**惯性和焦虑不能为空**。
**为什么**：只看推力和拉力会系统性高估需求。用户"很痛"但"不换"是常态。

### L6 · 机会卡片

**这一层在看**：把前五层收敛成一张能被独立看懂的卡片。

**结构**：`用户 × 场景 × 核心任务 × 现有方案的缺口 = 机会点`

**同时标注需求评估三角形**（定性，不定量）：

| 维度 | 判定 |
|------|------|
| 普遍性 | 多少人有这个任务 |
| 频次 | 多久发生一次 |
| 刚性 | 不解决的后果有多严重 |

**退出条件**：卡片脱离对话上下文也能被看懂；三角形三个维度都有定性判断。

## 自检闸门

- [ ] 全程每轮 ≤5 句　→ 不过，说明没执行本技能
- [ ] 每层都等了用户回应　→ 不过，重来
- [ ] 总轮次 5-7 轮　→ <4 轮多半没挖透，>9 轮多半跑偏
- [ ] L1 锚定的是**具体的人**不是人群标签　→ 不过回 L1
- [ ] L2 有具体时间地点动作　→ 不过回 L2
- [ ] L3 功能/情感/社会三层都有　→ 不过回 L3
- [ ] L4 有 ≥2 个替代方案且含"什么都不做"　→ 不过回 L4
- [ ] L5 惯性和焦虑非空　→ 不过回 L5
- [ ] L6 卡片能被独立看懂　→ 不过回 L6
- [ ] 全程 0 处"这个需求好/不好""建议你做"　→ 不过，改写
- [ ] 没有做定量测算　→ 不过，删掉并转科学决策

## 量化验收指标

| 指标 | 门槛 |
|------|------|
| 每轮句数 | ≤5 句 |
| 总轮次 | 5-7 轮 |
| 每层等待用户回应的比例 | 100% |
| 给选项的提问占比 | ≥70%（其余可以是追问） |
| L3 三层完整率 | 100% |
| L4 替代方案数 | ≥2 且含"什么都不做" |
| L5 四力完整率 | 100% |
| 评价句式出现次数 | **0** |
| 定量测算出现次数 | **0** |

## 常见失败模式

| 失败 | 表现 | 怎么避免 |
|------|------|---------|
| **一次性输出全流程** | 把 L1-L6 一口气抛出来 | **每层必等**，这是硬约束 |
| 每轮太长 | 一轮写了三百字 | ≤5 句 |
| 抛空题 | "你觉得用户需要什么？" | 给选项 |
| 接受人群标签 | "年轻人"就往下走 | L1 要具体的人 |
| 只问功能性 | L3 只答了"要完成什么事" | 三层都要 |
| 漏"什么都不做" | 替代方案只列了竞品 | 它是最强竞品 |
| 只看推力 | L5 只问了"现状多痛" | 惯性和焦虑必填 |
| 盯锤子 | 一直在聊产品功能 | 拉回"要完成什么任务" |
| 过早收敛 | 找到一个需求就停 | 追问"还有其他场景和用户吗" |
| 越界定量 | 开始算天花板 | 转科学决策 |
| 替他判断 | "这个需求挺强的" | 只呈现，不评价 |

## 降级与失败路径

| 情况 | 做法 |
|------|------|
| **他答不上来 L2 的具体情境** | 说明他还没有真实用户观察。如实说："这块目前是假设不是观察。要不要先去问 3 个真实用户？我们先把要问什么列出来。"——**转成访谈提纲，而不是硬编** |
| **他中途失去耐心** | 停在当前层，把已有的收敛成半张卡片，标注"推演到 L3，后三层待续"。**不催** |
| **他直接要结论** | 温和拉住："不急，咱们先看全。"如果他坚持，给出已推演部分 + 明确标注"以下基于 L1-L3，L4-L6 未做，判断可能偏乐观" |
| **缺关键数据** | 最多搜 3 个点（走 `quick-research`），搜完立刻回到推演 |
| **发现是商业模式问题不是需求问题** | 说："需求这层看起来是清楚的，卡点在怎么赚钱。要不要转五步法看全局？" |
| **发现他其实在纠结要不要做** | 说："这个像是要不要做的决策，不只是需求不清楚。要不要拉科学决策一起拆？" |

## 执行留痕与记忆写回

**留痕**：摘要保留六层的推演过程，任何时候能回答"这个结论是怎么推出来的、哪一层是观察哪一层是假设"。**必须标出哪些是真实观察、哪些是搭档的假设。**

**写回 `memory/demand/`**：分析的目标需求 / 用户画像与核心场景 / JTBD 三层任务 / 四种力量 / 关键假设与待验证项 / 机会卡片。

**长期沉淀 `MEMORY.md`**：**他容易在哪一层卡住**（这条直接决定你下次该在哪层多追一句）、已识别的需求锚点、他容易把什么当需求。

**技能记忆（L4）触发**：若某类产品（如工具类 SaaS）的 L3 情感性任务有稳定模式，沉淀成候选技能。
