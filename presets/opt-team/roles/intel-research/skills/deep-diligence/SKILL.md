# 深度尽调 · deep-diligence

> `oscar-research` 回答"这个赛道怎么样"，本技能回答"这一家到底什么底细"。
> 区别不在深浅，在于**钱要出去了**。所以这里多两道门：武器逐条决策，反向证据强制搜。

## 硬约束

1. **14 类武器逐条决策，不许留空。** 每一行必须写 ✅使用 / ⏭️跳过 / 📋线下，并给 **≥10 字的具体理由**。写"暂不需要""略"视为未完成。**未满足本步退出条件，不得进入下一步。**
2. **反向证据是独立的一道门，不是顺手搜一下。** 必须单独一轮，专搜负面：投诉、诉讼、处罚、离职吐槽、加盟商维权、数据存疑。**这一轮没搜，报告不许生成。**
3. **不给"投/不投"。** 交事实卡片、置信度、风险清单，判断权在搭档。
4. **每条事实一张卡**：结论 + 原文出处 + 发布年份 + 信源等级 + 是否有独立第二源。**没有卡片的说法不许进报告。**
5. **线下武器不代劳、不假装。** 需要搭档本人打电话、走门店、找熟人的，出行动指南和话术，明确标注"待搭档执行"，**绝不用网上找到的二手描述冒充实地信息**。

## 权限与数据边界

| 项 | 边界 |
|----|------|
| 读 | 本工作区 `memory/`、`references/`；联网公开信息 |
| 写 | 仅本工作区 `memory/`；**不写入任何其他 Agent 的工作区** |
| 外发 | **本技能不代替搭档接触被调研对象**。不发邮件、不投简历、不加客服、不提交任何表单 |
| 敏感数据 | 不把搭档的身份、投资意向、合作意图打进搜索串 —— 查询串会离开本机，也可能被对方看见 |
| 付费源 | 企业信息付费查询、第三方数据库，先问搭档 |
| 升权 | 不需要 `exec`、不需要 sudo、不安装任何包 |

## 何时使用 / 何时不用

| 场景 | 用不用 |
|------|--------|
| "这个加盟项目靠不靠谱" | ✅ 用 |
| "要不要投这家" | ✅ 用（只出信息，不出结论） |
| "这个竞品到底什么水平" | ✅ 用 |
| "预制菜赛道现在怎么样" | ❌ → `oscar-research` |
| "查一下他们去年营收" | ❌ → `point-intel` |
| "我该不该做这个决定" | ❌ → 科学决策 `roi-deep-dive`（本技能可作其输入） |

**升级信号**：查到一半发现主体不清（一个品牌背后三家公司互相担保）→ 先把股权与主体关系理清楚，再继续，别在错的主体上做完全套。
**降级信号**：搭档其实只想知道"有没有明显雷" → 走精简路径（Step 1 → 2 → 4 → 5），一轮反向证据 + 一页纸红旗清单。

## 输入输出契约

**输入**：一个具体主体（公司名 / 品牌名 / 项目名）+ 搭档要拿这份尽调做什么决定 + 时间与预算约束
**输出**：`assets/diligence-report.md` 格式的报告。必含：主体与关联方 / 14 行武器决策表 / 事实卡片库 / 反向证据专章 / 红旗清单 / 置信度与信息缺口 / 待搭档执行的线下行动指南
**上游**：`oscar-research` 的赛道结论（判断这家在行业里的位置）
**下游**：`roi-deep-dive` 的关键变量与风险输入
**串联示例**：`oscar-research`（看赛道）→ `deep-diligence`（挖这一家）→ `point-intel`（补关键数字）→ `roi-deep-dive`（算账）

## 流程

### Step 1 · 锁主体与用途

问清三件事：**查谁**（工商全称，不是品牌名）、**为什么查**（要做什么决定）、**多久要**。

顺手把关联方理出来：实际控制人、主要股东、同一控制人下的其他公司、历史更名。

**标准话术**：

> "先对一下：要查的是 **[工商全称]**，你拿它做 **[什么决定]**，**[多长时间]** 内要。另外这个品牌背后可能不止一家公司，我先把主体关系理清楚再往下挖。"

**退出条件**：主体确认到工商全称一级，用途明确。**未满足本步退出条件，不得进入下一步。**
**常见失败**：对着品牌名查了三天，最后发现签合同的是另一家壳公司。

### Step 2 · 填 14 行武器决策表（BLOCKING）

逐行决策，理由 ≥10 字。表格模板见 `assets/weapon-decision-table.md`，每类武器怎么用见 `references/weapons-14.md`。

| # | 武器 | 谁执行 |
|---|------|--------|
| 1 | 完整体验产品 | 搭档或 AI |
| 2 | 逆向数据分析 | AI |
| 3 | 直接访谈用户 | 搭档 |
| 4 | 收集产品口碑 | AI |
| 5 | 合作方研究 | AI |
| 6 | 内线情报 | 搭档 |
| 7 | 求职工具（招聘 JD 反推） | AI |
| 8 | 身份访谈 | 搭档 |
| 9 | 公司公开信息 | AI |
| 10 | 行业专家 | 搭档 |
| 11 | 第三方数据库 | AI（付费先问） |
| 12 | 行业报告 | AI |
| 13 | 其他公开信息 | AI |
| 14 | AI 工具与检索深度 | AI |

**退出条件**：14 行全部有状态和 ≥10 字理由，且明确了哪些是"待搭档执行"。
**常见失败**：只用第 9、12、13 三行（公开信息 + 行业报告 + 搜索），做出来的东西和搭档自己百度没差别。

### Step 3 · 采集与事实卡片化

按武器表执行。每拿到一条有用信息，立刻做成一张卡：

```
结论 | 原文出处（URL 或文件）| 发布年份 | 信源等级 A/B/C | 第二独立源 有/无
```

**独立源判定**：转载同一份通稿、引用同一家数据机构、被调研对象自报，**都不算两个独立源**。判不清就降一级并注明"上游可能同源"。

**退出条件**：P0 信息点覆盖率 ≥70%，且每条进报告的说法都有卡片。
**常见失败**：好查的查透，难查的悄悄略过，报告看起来很满，关键处全是空的。

### Step 4 · 反向证据强制门（BLOCKING）

**单独一轮，只搜负面。**关键词至少覆盖：

`XX 投诉` / `XX 诉讼` / `XX 处罚` / `XX 骗局` / `XX 维权` / `XX 跑路` / `XX 数据造假` / `XX 离职` / `XX 加盟商` / `XX 曝光`

同时查：司法涉诉、行政处罚、经营异常、股权冻结、社交平台与本地生活平台的差评聚集。

**退出条件**：十类关键词全搜过，结果（含"未发现"）逐条记录。**这一轮没做完，不得生成报告。**
**常见失败**：正面材料看多了产生好感，反向轮草草走个过场。**这一步的存在就是为了对抗这个偏置。**

### Step 5 · 红旗清单与交付

把发现按红旗分级：**红**（涉诉未结、处罚、实控人失信、加盟商集体维权）、**黄**（频繁更名、股权异常变动、口碑两极、关键数据只有自报）、**灰**（信息稀薄、查不到）。

**灰也要写。** 一家正经经营三年的公司什么都查不到，本身就是一个信息。

**退出条件**：自检闸门全过。

## 自检闸门

交付前逐条打勾，**有一条不过就回退到对应步骤**：

- [ ] 主体确认到工商全称，关联方已理清　→ 不过回 Step 1
- [ ] 14 行武器表全填，理由均 ≥10 字　→ 不过回 Step 2
- [ ] 线下武器已标注"待搭档执行"并附话术　→ 不过回 Step 2
- [ ] 每条进报告的说法都有事实卡片　→ 不过回 Step 3
- [ ] 关键结论有 ≥2 个独立源，或已标"单一来源"　→ 不过回 Step 3
- [ ] 反向证据十类关键词全搜过并逐条记录　→ 不过回 Step 4
- [ ] 红黄灰三级红旗清单齐全　→ 不过回 Step 5
- [ ] 全文没有"建议投""值得做""风险可控"　→ 不过回 Step 5
- [ ] 查询串里没有搭档的身份与意图　→ 不过，立即向搭档报告

## 量化验收指标

| 指标 | 门槛 |
|------|------|
| 武器决策表填写率 | **14/14**，理由均 ≥10 字 |
| 实际使用的武器类别数 | ≥5 类（低于 5 类等同于普通搜索） |
| 反向证据关键词覆盖 | **10/10** |
| P0 信息点覆盖率 | ≥70% |
| 事实卡片五字段齐全率 | **100%** |
| 关键结论的独立源数 | ≥2（否则显式标注单一来源） |
| 报告中的建议句式 | **0** |
| 未找到项的替代渠道覆盖率 | **100%** |

## 常见失败模式

| 失败 | 表现 | 怎么避免 |
|------|------|---------|
| 查错主体 | 品牌名查一圈，签约方是另一家 | Step 1 锁工商全称 |
| 三行武器 | 只做公开信息 + 报告 + 搜索 | 14 行逐条决策 |
| 反向证据走过场 | "未发现明显负面"一句话带过 | 十类关键词逐条留痕 |
| 好感偏置 | 官网和融资新闻看多了，语气变软 | 反向轮独立成门 |
| 同源伪独立 | 三篇报道转同一份通稿 | 每条追上游 |
| 假装实地 | 用大众点评评论冒充走访 | 线下武器标"待执行" |
| 越界给结论 | 末尾加一句"整体看还是靠谱的" | 建议句式零容忍 |
| 灰色不报 | 查不到就不写 | 查不到本身是情报 |

## 降级与失败路径

**信息稀薄查不到**：如实说"公开渠道拿不到"，说清搜了几轮、用过哪些关键词，并给具体替代渠道：

| 缺什么 | 替代渠道 |
|--------|---------|
| 经营数据 | 招股书 / 关联上市公司公告 / 招聘 JD 反推团队规模 / 供应商访谈 |
| 真实口碑 | 本地生活平台差评聚集 / 二手转让平台的设备出货 / 离职员工社区 |
| 加盟真实回报 | 找 3 位现有加盟商直接问（**待搭档执行**，附话术） |
| 涉诉与处罚 | 司法公开网 / 信用信息公示系统 / 行政处罚公示 |

**时间不够**：走精简路径（Step 1 → 2 → 4 → 5），只交红旗清单 + 反向证据专章，明确标注"未做全量尽调"。**反向证据那一门任何情况下不许跳。**

**搭档催着要结论**：给信息与置信度，不给结论。可以说"这几条是红旗，这几条查不到"，**不能说"我觉得可以做"**。

## 执行留痕与记忆写回

**留痕**：报告保留武器决策表原件、每轮搜索的关键词清单、每张事实卡的抓取时间。任何人可按图复现这次尽调，也可在三个月后判断哪些结论已经过期。

**写回 `memory/YYYY-MM-DD.md`**：

1. 查了哪个主体、为什么查、搭档拿它做什么决定
2. 用了哪几类武器、哪几类跳过了、为什么
3. 反向证据轮的完整结果（**含"未发现"** —— 下次复查时这是基线）
4. 待搭档执行的线下动作，以及他后来做了没有、结果是什么

**沉淀进 `MEMORY.md` 的可信度校准记录**：这次哪个信源给力、哪个是坑；哪类主体在哪个渠道最容易查到底细。**做过三次尽调之后，这份记录比任何检索技巧都值钱。**
