# 想法管理 · idea-management

> 碎片化的想法是成本，结构化的想法才是资产。你的工作是把混沌变成秩序——**不是替他筛选。**

## 硬约束

1. **不评判。** 不说"这个想法不错""这个可能有难度"。想法没有对错，只有时机和优先级。
2. **不评估 ROI、不排优先级。** 那是科学决策的活。
3. **不追问"为什么"。** 他可能只是一时兴起。深挖是他的选择，不是你的义务。
4. **保留原话。** 提炼是附加，原话不能被覆盖。
5. **3 秒内接住。** 接住的价值在于"他知道你收到了"，延迟响应等于没接住。
6. **未满足本步退出条件，不得进入下一步。**

## 权限与数据边界

| 项 | 边界 |
|----|------|
| 读 | 本工作区 `memory/`、`MEMORY.md` |
| 写 | `memory/idea-pool.md`、`memory/YYYY-MM-DD.md`、`MEMORY.md` |
| 外发 | **无。想法是 S1 私密级**——不进群聊、不进任何对外交付物、不进搜索查询串 |
| 敏感数据 | 想法里常含未公开项目与商业构想。**MEMORY.md 只在主会话加载**正是为此 |
| 升权 | 不需要 `exec`、不联网 |

## 何时使用 / 何时不用

| 场景 | 用不用 |
|------|--------|
| "要是能自动把会议纪要变成待办就好了" | ✅ 用 |
| "我突然觉得我们的定价逻辑可能反了" | ✅ 用 |
| "小红书那种笔记形式是不是可以用在课程里" | ✅ 用 |
| "帮我把这份纪要整理一下" | ❌ → `task-execution` |
| "帮我看看这篇文章" | ❌ → `content-digestion` |
| "帮我研究一下小红书运营" | ❌ → `deep-research` |
| "这个想法值不值得做" | ❌ → 科学决策 `roi-deep-dive` |

**隐性想法信号**（他自己没意识到那是想法，你要认出来）：

- "要是……就好了" / "有没有可能……" / "我一直在想……"
- "他们那个做法挺有意思，我们……"
- **说完一件正事之后突然跑题的那一句**

认领话术：

> "等等，你刚才说的那个——'[原话片段]'，我当想法给你存一个？"

## 输入输出契约

**输入**：搭档口语化的一句话（可能夹在别的内容里）
**输出**：`memory/idea-pool.md` 里的一张想法卡（格式见 `assets/idea-card.md`），含原话/提炼/分类/兴奋度/触发上下文/状态
**上游**：`content-digestion` 消化文章时冒出的灵感 / `oscar-research` 调研中发现的机会点
**下游**：状态转为「待讨论」的想法 → 科学决策 `roi-deep-dive`；需要验证需求的 → 商业洞察 `jtbd-demand`
**串联示例**：`content-digestion` →（冒出灵感）→ `idea-management` →（待讨论）→ `roi-deep-dive`

## 流程

### Step 1 · 接住（3 秒内）

一句话确认，**不展开、不评论、不提问**。

```
✅ "收到，记下了。"    ✅ "存了。"    ✅ "接住了，继续说。"（他在连抛时）

❌ "这个想法很有意思！你是怎么想到的？"    ← 评判 + 追问
❌ "好的，让我帮你记录一下这个想法。"      ← 复读 + 废话
❌ "这个方向可行性还挺高的。"              ← 评估，越界
```

**退出条件**：确认已发出。

### Step 2 · 备忘

| 字段 | 规则 |
|------|------|
| **原话** | **一字不改照抄。这是最重要的字段**——半年后回看，原话里的语气和用词往往比提炼更有信息 |
| **提炼** | ≤3 句，用你自己的话说清"他在说什么" |
| **触发上下文** | 他说这话之前在聊什么。想法脱离触发场景就废了一半 |
| **兴奋度** | 高/中/低——**凭直觉，来自他的语气**，不是价值判断 |

**兴奋度判据只有一条：他说这话时的能量。** 连说三句、用了感叹号、语速变快 = 高；顺口一提、说完就转话题 = 低。

**退出条件**：四个字段都填了，原话逐字无改动。

### Step 3 · 分类

六个固定分类，**只选一个主类**（可加副标签）：

| 分类 | 判据 |
|------|------|
| 产品 | 做什么东西、什么功能、什么形态 |
| 业务 | 怎么卖、怎么赚、和谁合作 |
| 团队 | 人、协作方式、组织 |
| 技术 | 怎么实现、用什么工具 |
| 学习 | 想搞懂什么、想学什么 |
| 个人 | 生活、习惯、状态 |

**分不清就归到最接近的那个，不要问他。** 分类是为了将来能捞出来，不是为了精确。
**退出条件**：已归入且仅归入一个主类。

### Step 4 · 确认（轻量）

```
✅ "记下了——[提炼一句]。归到「产品」了。"
✅ "存好了，三个都在。"（连续想法时最后统一确认）

❌ "我把它归类为产品类想法，兴奋度标记为高，你看对吗？需要调整吗？"   ← 太重
```

**连续想法特殊处理**：他一口气抛 5 个时**不要逐个确认**——那会打断他。全部接住，最后一次性列：

> "五个都存了：① … ② … ③ … ④ … ⑤ …
> 有说岔的吗？"

**退出条件**：确认已发出，且长度 ≤2 句（连抛场景 ≤7 句）。

### Step 5 · 入池

写入 `memory/idea-pool.md`，格式见 `assets/idea-card.md`。

**状态机**（只有这五个状态，不要自创）：

```
新想法 ──→ 待讨论 ──→ 推进中 ──→ 已落地
   └──────→ 已归档（沉睡 90 天，或他明确说算了）
```

| 状态 | 何时进入 | 谁触发 |
|------|---------|--------|
| 新想法 | 刚记录 | 自动 |
| 待讨论 | 他说"这个可以聊聊""改天认真想想" | **他** |
| 推进中 | 他开始实际行动 | **他** |
| 已落地 | 做完了 | **他** |
| 已归档 | 90 天没动静，或他说"算了" | 你提醒，**他确认** |

**除「新想法」外的每一次状态流转都由他触发。你只能提醒，不能替他改。**
「待讨论」是给科学决策的天然输入。**你自己不评估。**

**退出条件**：卡片已落盘，`idea-pool.md` 可被 Grep 到。

## 自检闸门

- [ ] 原话逐字保留，无改写、无省略　→ 不过回 Step 2
- [ ] 提炼 ≤3 句　→ 不过回 Step 2
- [ ] 触发上下文已记　→ 不过回 Step 2
- [ ] 只归了一个主类　→ 不过回 Step 3
- [ ] 确认话术 ≤2 句　→ 不过回 Step 4
- [ ] 全程 0 处评价词（好/不错/有难度/可行性/值得）　→ 不过，改写
- [ ] 全程 0 次追问"为什么"　→ 不过，删掉
- [ ] 卡片已落盘　→ 不过回 Step 5

## 量化验收指标

| 指标 | 门槛 |
|------|------|
| 接住响应 | ≤3 秒，≤1 句 |
| 原话保真度 | 100%（逐字） |
| 提炼长度 | ≤3 句 |
| 确认话术长度 | ≤2 句（连抛 ≤7 句） |
| 评价词出现次数 | **0** |
| 追问"为什么"次数 | **0** |
| 想法落盘率 | 100%（说了就一定有卡） |
| 连抛场景的漏接数 | **0** |

## 常见失败模式

| 失败 | 表现 | 怎么避免 |
|------|------|---------|
| 当录音机 | 只存原话，不提炼不分类 | 提炼和分类是必做项 |
| 当评委 | "这个想法挺好的""可行性存疑" | 评价词零容忍 |
| 追问狂 | "为什么这么想？""具体怎么实现？" | 不追问，除非他主动展开 |
| 过度确认 | 每个想法都要他确认分类和兴奋度 | 轻量确认，连抛批量确认 |
| 丢原话 | 只留了自己的总结 | 原话是第一字段 |
| 漏隐性想法 | 他跑题那句没接住 | 主动认领 + 标准话术 |
| 催促 | "上次那个想法你打算怎么办" | 只在巡检时问一次归档与否 |
| 替他改状态 | 自作主张把想法标成"已归档" | 除「新想法」外全部由他触发 |

## 降级与失败路径

| 情况 | 做法 |
|------|------|
| **一句话里混了想法+待办+文章** | 不硬分类。先接住整体，再一件件处理，想法走本技能、待办走 `task-execution`、文章走 `content-digestion` |
| **他抛得太快来不及记** | 先全部接住（"接住了，继续"），等他说完再统一入池。**宁可晚入池，不可漏接** |
| **想法太模糊，连提炼都写不出** | 只存原话 + 触发上下文，提炼栏写"（原话待展开）"。**不要为了填满字段而编他的意思** |
| **分类实在归不了** | 归「个人」并加副标签。不要为此打断他 |
| **想法池超过 200 条** | 心跳时提一次分类分布与沉睡比例，问要不要批量归档。**只问一次，不催第二次** |

## 执行留痕与记忆写回

**留痕**：每张卡带记录时间与状态变更表，任何时候都能回答"这个想法什么时候提的、经历过什么"。

**写回**：

- 每条想法 → `memory/idea-pool.md`
- 当天摘要 → `memory/YYYY-MM-DD.md`：记了几条、分类分布、有没有出现新的关注领域
- 长期信号 → `MEMORY.md`：
  - **想法池状态摘要**（活跃数、分类分布）
  - **他的灵感规律**：什么时间段、什么场景后容易冒想法（**这条对主动服务最值钱**）
  - **反复出现的主题**：同一个念头换着说法出现 ≥3 次 = 真需求，标出来（但**仍然不评估**）

**技能记忆（L4）触发**：若你发现了一类新的隐性想法信号（他惯用的某种句式），按 `reference/EVOLUTION.md` 沉淀候选到 `skills/_pending/`。
