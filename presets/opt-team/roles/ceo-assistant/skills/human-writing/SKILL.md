# 活人感写作 · human-writing

> 活人感首先来自材料，其次来自说话位置，最后才是语气。
> 顺序反过来就是 AI 腔：先摆姿势，再找话说。

## 硬约束

1. **非虚构稿动笔前先数材料。** 计划超过 1200 字的现实稿，内部必须先逐条列出 **≥5 件具体材料**（事实、数字、原话、案例、反例各算一件），并注明每件来自搭档哪句话或哪份来源。**未满足本步退出条件，不得进入下一步。**
2. **材料不够只有三条路**：能查就查、一次问完最多三个问题、缩小题目交短稿。**绝不用重复解释、假设场景、比喻换场填字数。**
3. **不给现实稿伪造细节。** 没有来源的精确时间、天气、神态、房间摆设、对白，一律不写。假细节越具体，AI 味越重。
4. **禁用项清零才算成稿**，见「量化验收指标」。命中一项就不能交。
5. **只交作品。** 不输出提纲、字数统计、写作说明、规则复述，结尾不额外总结全文。

## 权限与数据边界

| 项 | 边界 |
|----|------|
| 读 | 本工作区 `memory/`、`references/`；搭档明确交来的素材 |
| 写 | 稿件文件 + 本工作区 `memory/`；**不写入任何其他 Agent 的工作区** |
| 外发 | 无。本技能只产出文本，不发布、不投稿、不提交任何表单 |
| 敏感数据 | 搭档的私人经历、内部数据、客户名，未经明确许可不写进对外稿件 |
| 升权 | 仅需执行本技能自带的 `scripts/check_prose.py`；不装包、不联网、不 sudo |

## 何时使用 / 何时不用

| 场景 | 用不用 |
|------|--------|
| "这段讲师话术太 AI 了，改改" | ✅ 用 |
| "把这份调研写成给学员看的材料" | ✅ 用 |
| "写一段 3 分钟口播" | ✅ 用 |
| "帮我查一下这个数据" | ❌ → `point-intel` |
| "这个行业怎么样" | ❌ → `oscar-research` |
| "生成一份完整课程包" | ❌ → `course-material-pack`（成稿后再用本技能过一遍） |

**升级信号**：改到第三遍发现问题不在文字而在材料太薄 → 停下来告诉搭档"这稿子缺的不是润色，是三件具体的事"，转去补材料。
**降级信号**：搭档只要一句话文案 → 不走七遍流程，直接给两三个版本让他挑。

## 输入输出契约

**输入**：一份初稿或一个写作任务 + 素材（搭档的话 / 已核实的调研结论 / 课程内容）
**输出**：可直接使用的成稿（Markdown），禁用项清零
**上游**：`point-intel` / `oscar-research` / `deep-diligence` 的已核实结论；`course-material-pack` 的物料初稿
**下游**：任何对外交付物的最后一道工序
**串联示例**：`course-material-pack`（出物料）→ `human-writing`（过七遍）→ 交付

## 流程

### Step 1 · 数材料（现实稿必做）

列出 ≥5 件具体材料并标注来路。五件要能串成一条过程或一条论证链，**不能是五句相邻的道理**。每再多约 800 字，至少再备一件。

**退出条件**：五件材料写完且每件都有来路。列不出来就走「降级与失败路径」，**不得进入下一步**。
**常见失败**：把"输入更方便""能保留状态""能找回旧内容"三条抽象想法，分别补上用途、意义、风险、未来，写成十几段。这仍然只有三条材料。

### Step 2 · 找说话位置

内部回答五件事，答案不交给搭档：谁在说 / 什么事让他现在想说 / 手里有哪些能托住文章的东西 / 他对哪一点有明确判断、依据到哪为止 / 读者看完上一段最自然会追问什么。

**退出条件**：五问都有具体答案，第三问不是空的。
**常见失败**：用"我觉得""说真的"修复匿名感。声音来自取舍，不来自代词。

### Step 3 · 写第一稿

- 开头尽快碰到事情，不预告全文结构
- 分类必须来自材料，不拿"三个原因四个阶段"代替文章
- 能用自然段说清就不用项目符号，只有严格先后的操作步骤才允许列表
- 新段落必须增加新东西；换个说法不算推进
- 先让主语和动作出现，再接时间、原因、条件
- 动作和细节已经把感情写出来就停，不替读者解释
- 写完就停，不升华、不首尾呼应、不在末段重摘全文

**退出条件**：全篇每段都能说出"这段新增了什么"。
**常见失败**：连续几段用同一句短判断收尾，全篇像语录集。

### Step 4 · 七遍改稿（顺序不能乱）

必须按此序，详细判据见 `references/revision.md`：

| 遍次 | 干什么 | 不过的处理 |
|------|--------|-----------|
| 一 | 看谁在说 —— 哪几段换个模型也能原样写出来 | 补信息来路或删 |
| 二 | 看有没有往前走 —— 每段标作用，做压缩试验 | 删到长度与材料相称 |
| 三 | 拆表演性中文 —— 假深刻 / 假具体 / 假口语 / 抽象名词 / 比喻换场 | 还原成本义 |
| 四 | 听中文顺不顺 —— 主干早点来，"的"字堆叠，词序与停顿 | 重排语序 |
| 五 | 清禁用项 | 逐条改写，不换漂亮句式 |
| 六 | 核事实或设定 | 核不实就删，不留"大概" |
| 七 | 查结尾 | 事情讲完就停 |

**退出条件**：七遍全走完，且第五遍机检为 0。**未满足本步退出条件，不得进入下一步。**
**常见失败**：把清禁用项挪到最后一遍。标点是第五遍不是第七遍，顺序颠倒会把前四遍的改动重新污染。

### Step 5 · 机检与交付

有 python3 时跑 `python3 scripts/check_prose.py <稿件路径>`，脚本报错就继续改到清零；没有 python3 就按「量化验收指标」逐条人工核。

**退出条件**：自检闸门全过。

## 自检闸门

交付前逐条打勾，**有一条不过就回退到对应步骤**：

- [ ] 现实稿列得出 ≥5 件具体材料且各有来路　→ 不过回 Step 1
- [ ] 每段都能说出新增了什么　→ 不过回 Step 4 第二遍
- [ ] 没有无来源的时间、天气、神态、摆设、对白　→ 不过回 Step 4 第三遍
- [ ] 禁用项机检为 0　→ 不过回 Step 4 第五遍
- [ ] 事实、数字、引语全部核过　→ 不过回 Step 4 第六遍
- [ ] 结尾没有升华、没有重摘全文　→ 不过回 Step 4 第七遍
- [ ] 交付物里没有提纲、字数统计、写作说明　→ 不过回 Step 5
- [ ] 没把搭档的私人信息写进对外稿　→ 不过，立即向搭档报告

## 量化验收指标

| 指标 | 门槛 |
|------|------|
| 现实稿材料件数 | ≥5 件（每增 800 字 +1 件） |
| 中文冒号 `：` 与英文冒号 | **0**（网址、代码、机器字段、剧本台词、钟点除外） |
| 破折号 `——` / `—` / `–` | **0** |
| "不是……而是……"及同结构翻案句 | **0** |
| 叹号 | **0** |
| 表情符号作小标题 | **0** |
| "说白了""先说结论""值得注意的是"类路标 | **0** |
| 压缩试验 | 删掉三分之一后信息量明显下降（下降不明显说明在注水） |
| 交付物中的过程说明字数 | **0** |

## 常见失败模式

| 失败 | 表现 | 怎么避免 |
|------|------|---------|
| 材料不够硬写 | 三条想法写成十几段 | Step 1 是硬门 |
| 穿论坛服装 | 烟头、冷馒头、深夜屏幕凭空出现 | 现实稿无来源细节一律删 |
| 顺序颠倒 | 先清标点再改结构，改完又生出新禁用项 | 七遍顺序写死 |
| 换句式不换内容 | 把禁用句式替换成另一种漂亮句式 | 先找它原本想说的事实，用普通句子说出来 |
| 替读者解释 | 细节后面追一句"这说明了……" | 动作写到位就停 |
| 交付带过程 | 附上提纲、字数、自检清单 | 只交作品 |
| 顺手编经历 | 把新经历安到搭档身上 | 不许追问时缩小题目，不补经历 |

## 降级与失败路径

**材料不够是常态，不是失败。**

1. 事实型题目有公开材料可查 → 先查，查完重新数。有检索能力却没检索，等于没材料。
2. 依赖搭档的私人体验 → **一次问完，最多三个问题**（你和这件事实际发生过什么关系 / 哪个瞬间或数字最让你在意 / 你现在最想说的判断是什么），此时不要同时交稿。
3. 搭档明确不许追问 → 缩小题目，交一篇不超过 600 字的短答。**宁可明显短于目标字数，也不能用假例子填满。**

**时间不够时**：优先保证第一、二、五、六遍（说话位置 / 推进 / 禁用项 / 事实），第三、四、七遍可标注"未过"，但不得声称已完稿。
**没有 python3**：按「量化验收指标」逐项 Grep 人工核，并在交付时注明机检未跑。

## 执行留痕与记忆写回

**留痕**：改稿任务保留一份改前稿（`memory/drafts/` 下带日期），任何人可比对七遍改了什么。

**写回 `memory/YYYY-MM-DD.md`**：

1. 这次写的是什么、给谁看
2. 材料从哪来、哪几件是搭档给的
3. 机检命中了哪些禁用项（这是最有复利的一条 —— 反复命中的项说明是稳定习惯，下次第一稿就该避开）
4. 搭档退回重改的地方与原话

**沉淀进 `MEMORY.md`**：搭档对文风的稳定偏好（能接受多长、喜欢什么开头、讨厌什么词），以及本工作区高频命中的禁用项 Top 3。
