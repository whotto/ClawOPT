# 单点情报挖掘 · point-intel

> 把一个明确的问题挖到底。拿到就交付带可信度的答案，拿不到就诚实说拿不到并给替代渠道。

## 硬约束

1. **搜不到不许编。** 任何具体数字、日期、人名、机构名，只要不是实际检索到的，就不许写进交付物。
2. **不给结论。** 交付信息和可信度判断，不说"所以这个能做/不能做"。
3. **一轮不叫饱和。** 未达到 §流程 Step 3 的六项指标之前，不许说"没找到"。
4. **每条重要信息三标签**：来源 + 年份 + 可信度等级。缺一条就是不合格交付。
5. **未满足本步退出条件，不得进入下一步。**

## 权限与数据边界

| 项 | 边界 |
|----|------|
| 读 | 本工作区 `memory/`；联网公开信息 |
| 写 | 仅本工作区 `memory/`；**不写入任何其他 Agent 的工作区** |
| 外发 | 无。本技能不产生任何对外发送动作（不发邮件、不发帖、不提交表单） |
| 敏感数据 | **不把搭档的私人信息、公司内部数据、未公开项目名带进搜索查询串**——查询串会离开本机 |
| 付费源 | 涉及付费数据源必须先问搭档，不擅自消费 |
| 升权 | 不需要 `exec`、不需要 sudo、不安装任何包 |

## 何时使用 / 何时不用

| 场景 | 用不用 |
|------|--------|
| "2025 年中国宠物食品市场规模多少" | ✅ 用 |
| "XX 公司的融资历史" | ✅ 用 |
| "这个政策什么时候出的，原文在哪" | ✅ 用 |
| "帮我核实一下这个数字对不对" | ✅ 用 |
| "宠物赛道值不值得进" | ❌ → `oscar-research` |
| "我该不该做这个决定" | ❌ → 科学决策 `roi-deep-dive` |
| "用户到底要什么" | ❌ → 商业洞察 `jtbd-demand` |

**升级信号**：查着查着发现要回答的其实是多维度问题 → 主动说"这个问题可能需要走完整的系统调研，咱们把目标定一下？"转 `oscar-research`。

## 输入输出契约

**输入**：一句可判真假的信息需求（或一句模糊需求，由 Step 1 转成可判真假的）
**输出**：`assets/point-delivery.md` 格式的一页纸。必含字段：答案句 / 关键数据表（值·口径·年份·来源·可信度）/ 交叉验证情况 / 未找到清单 / 推算部分（如有）
**上游**：`oscar-research` 的 R1 信息点清单可逐条喂给本技能
**下游**：`roi-deep-dive` 的关键变量验证 / `five-steps-quick` 的假设验证 / `team-health-diagnosis` 的外部基线
**串联示例**：`oscar-research`(R1) → `point-intel` ×N → `oscar-research`(A2/R2)

## 流程

### Step 1 · 确认信息需求

**目标**：把"要查什么"锁死成一句可判定真假的信息陈述。

**标准话术**：

> "咱们对一下，你要的是：**[具体信息点]**，时间范围 **[年份]**，口径是 **[整体/细分/某地区]**。对吗？"

**三个关键参数**（缺哪个补哪个，**不要一次问三个**）：

| 参数 | 为什么必须 |
|------|-----------|
| 口径 | "市场规模"是出货量、零售额还是产值？差三倍很常见 |
| 时间 | 最新数据 vs 某一年数据，检索路径完全不同 |
| 用途 | 决定精度要求。做 PPT 引用要权威源；自己心里有数量级则不必死磕 |

**退出条件**：用户确认了这句信息陈述，或明确说"你看着办"。
**例外**：用户已说得非常具体（"查宁德时代 2025 年报的动力电池毛利率"）→ 跳过确认直接搜。**不要为走流程而问废话。**
**常见失败**：一次抛三个参数问题，把用户问烦。

### Step 2 · 搜索提案（仅复杂检索时做）

信息点冷门、口径多样、或预计要搜 5 轮以上时，先说打算怎么搜：

> "我打算从三个方向搜：① 官方统计口径 ② 头部行业报告 ③ 上市公司财报里的同口径披露。有没有你已经看过、不用重复的？"

简单检索**跳过这一步**。
**退出条件**：用户点头，或本步被判定为可跳过。

### Step 3 · 饱和式搜索（核心）

**"搜了一下没找到"不叫搜过。** 六项硬指标：

| 维度 | 硬指标 |
|------|--------|
| 关键词组数 | **≥3 组**不同表述：行业术语 / 口语说法 / 英文对应词 / 上位概念 / 下位概念 |
| 语种 | 中英文都搜；涉及日韩欧市场补当地语种 |
| 来源类型 | **≥3 类**：官方与监管 / 行业报告 / 媒体报道 / 从业者社区 / 财报与招股书 |
| 反面证据 | **必搜 1 轮**：`XX 失败`、`XX 争议`、`XX 数据存疑`、`XX 造假` |
| 上游追溯 | 拿到数字后追一层：这个数字最早出自哪里 |
| 停止条件 | 新一轮不再产生新增信息点（信息收敛），或已确认公开渠道拿不到 |

**关键词构造示例**（查"宠物食品市场规模"）：

```
行业术语：宠物食品 市场规模 / 宠物食品 行业规模 亿元
口语说法：狗粮猫粮 一年卖多少钱
英文：China pet food market size
上位概念：宠物经济 市场规模（再拆宠物食品占比）
下位概念：犬粮 市场规模 + 猫粮 市场规模（加总倒推）
反面：宠物食品 市场规模 数据 存疑 / 口径 差异
```

**搜索中的实时纪律**：

- 每拿到一个数字，立刻记三件事：**出处 URL、发布年份、原始口径**
- 遇到"据统计""业内人士称""相关数据显示"这类无主语表述 → 标为二手，继续追上游
- 遇到多个数字打架 → **不要挑一个信**，全部记下来交给 Step 4

**退出条件**：六项全部达标。
**常见失败**：好搜的搜了，难搜的悄悄略过。

### Step 4 · 交叉验证

**"独立来源"的判定**（最常被糊弄的一步）。以下**不算**两个独立来源：

- 两家媒体转载同一份新闻通稿
- 两份报告引用同一家数据机构
- 榜单/百科/聚合站，其数据源是被统计对象自报

**判不清上游时：降一级处理，并在交付物里注明"上游可能同源"。**

**数字打架的处理**：

| 情况 | 做法 |
|------|------|
| 口径不同 | 全部保留，各自标口径，**不做加权平均** |
| 年份不同 | 全部保留，标年份，指出增长趋势 |
| 同口径同年份但数字不同 | 全部呈现，比较来源权威性，标"存在分歧"，**不替用户选一个** |

**时效降级**：超过 24 个月的市场类数据默认降一级，标注"数据较旧，需要验证"。

**退出条件**：所有 A 级结论都有 ≥2 个独立来源，或已显式降级标注。

### Step 5 · 交付

用 `assets/point-delivery.md`。**结论先行**：第一句就是答案，搜索过程放后面。
**退出条件**：自检闸门全过。

## 自检闸门

交付前逐条打勾，**有一条不过就回退到对应步骤**：

- [ ] 每条重要信息有 **来源 + 年份 + 可信度等级**　→ 不过回 Step 3
- [ ] 关键结论有 ≥2 个**独立**来源，或已标注"单一来源"　→ 不过回 Step 4
- [ ] 搜过反面证据　→ 不过回 Step 3
- [ ] 所有数字都是**实际检索到的**，无一来自推算或印象　→ 不过回 Step 3
- [ ] 推算部分已显式标注"（推测，依据：……）"　→ 不过回 Step 5
- [ ] 未找到的信息已进缺口清单，附搜索轮次与替代渠道　→ 不过回 Step 5
- [ ] 全文没有"建议你""所以应该""这个能做"　→ 不过回 Step 5
- [ ] 查询串里没有搭档的私人或内部信息　→ 不过，立即向搭档报告

## 量化验收指标

| 指标 | 门槛 |
|------|------|
| 关键词组数 | ≥3 组 |
| 来源类型数 | ≥3 类 |
| 反面证据轮次 | ≥1 轮 |
| 关键结论的独立来源数 | ≥2 个（否则必须显式标"单一来源"） |
| 带三标签的信息占比 | 100% |
| 交付物中建议句式出现次数 | **0** |
| 未找到项的替代渠道覆盖率 | 100%（每条都要给替代渠道） |

## 常见失败模式

| 失败 | 表现 | 怎么避免 |
|------|------|---------|
| 一轮就收 | 搜索引擎首页扫一眼就说"找到了/没找到" | 六项指标是硬门槛 |
| 同源伪独立 | 三篇文章都转同一份通稿，当成三个来源 | 每条都追上游 |
| 口径混用 | 把出货量和零售额混着比 | 每个数字标口径 |
| 偷偷补全 | 搜到 2023 年数据，写成"目前约为" | 年份必标 |
| 越界给结论 | 末尾加一句"所以这个赛道还不错" | 建议句式零容忍 |
| 信息茧房 | 只搜到支持某个方向的证据 | 反面证据是必搜项 |
| 泄密式检索 | 把公司内部项目代号打进搜索框 | 查询串脱敏是硬约束 |

## 降级与失败路径

**搜不到是能力，不是失败。绝不能做**：编一个数、给一个"大概是"、用行业常识糊过去。

**应该做**：

1. 明确说"公开渠道拿不到"，说清搜了几轮、用过哪些关键词
2. 给**具体的**替代获取渠道：

| 类型 | 替代渠道 |
|------|---------|
| 行业规模 | 行业协会年鉴 / 头部上市公司财报倒推 / 海关进出口数据 |
| 竞品经营数据 | 招股书 / 招聘 JD 反推团队规模 / 供应链访谈 |
| 用户行为 | 应用商店评论抓取 / 第三方数据平台试用版 / 小样本自采 |
| 政策细则 | 地方政务网站 / 政府信息公开申请 |

3. 给可推算的替代路径并**显式标注为推算**：

> "直接数据没有。可以从 A（✅A 级）× B（⚠️B 级）粗算出数量级约 X——**这是推算不是实测，只能判断量级，不能引用。**"

**时间不够时**：优先保证 P0 信息点的三标签完整，其余标"未验证"，绝不为赶时间降低标注标准。

## 执行留痕与记忆写回

**留痕**（可审计）：每次检索在交付物里保留「搜索轮次 + 用过的关键词 + 命中来源」，任何人可按图复现这次检索。

**写回 `memory/YYYY-MM-DD.md`**：

1. 查了什么、为什么查（决策背景）
2. 找到的关键信息 + 来源
3. **没找到的 + 已试过的关键词 + 替代渠道**（下次接着挖，不重复劳动）
4. 信源表现：哪个源这次给力、哪个是坑

**沉淀进 `MEMORY.md` 的「可信度校准记录」**：哪些信源实际验证过靠谱、哪些翻过车。**这是本技能最有复利的沉淀**——三个月后它比任何搜索技巧都值钱。

可信度分级完整判据见 `reference/credibility-standards.md`（工作区根目录，团队共用）。
