# 讲师手册模板

> 验收标准：一个没参与设计的讲师，拿着它能把这堂课上完。
> 每个模块必须写全五件事。写不出来的那一件，就是这个模块还没设计完。

## 封面信息

```markdown
# 讲师手册 · <课程名>

- 时长：<X 小时>
- 人数：<Y 人>
- 学员：<画像一句话>
- 能力目标：<结束时学员能做的具体动作>
- 所需材料：<白板 / 便利贴 / 每组一台电脑 / 提前开好的账号>
- 讲师准备：<课前必须自己跑通的东西，写清楚>
```

## 时间总表（分钟数必须加总等于总时长）

## 每个模块的五件事

### 模块 <N> · <名称>（<X> min）

#### 1. 讲师话术

写成能直接念出口的句子。

```
"<开场白原话。引出问题，先不给答案。>"

"<抛场景时的原话，把三毒说出来：信息矛盾、时间压力、代价不对称。>"
```

#### 2. 题目

场景题或诊断题原文，附带：

- 常见答案 A 代表的思维路径：<……>
- 常见答案 B 代表的思维路径：<……>
- 没有绝对正确答案时，写清楚"这题不评对错，评理由"

#### 3. 观察要点

| 学员行为 | 说明他处在 | 讲师该做什么 |
|---------|-----------|-------------|
| 直接问"标准答案是什么" | 旁观者 | 把问题推回去，问他会怎么开始 |
| 上来就分析数据缺口 | 使用者 | 追问他准备怎么补 |
| 先问"这个决定谁来拍板" | 指挥者 | 让他给全组讲一遍 |

#### 4. 追问话术

| 学员选了 | 怎么追问 |
|---------|---------|
| A | "如果按这个逻辑推下去，遇到 <极端情况> 会怎么办？" |
| B | "我不同意。<相反立场>。你怎么说服我？" |
| 说不出理由 | "先别管对错。你脑子里第一个闪过的画面是什么？" |

追问的铁律：**永远不说"你错了"。让学员自己发现问题。防御状态的人学不到东西。**

#### 5. 应对预案

| 情况 | 怎么处理 |
|------|---------|
| 冷场 | <具体动作，比如点名两个已经写完的人先讲> |
| 有人抬杠 | <把他的反例接过来当下一个场景> |
| 超时 10 分钟 | <砍哪一块，写死。不要现场纠结> |
| 学员水平差距大 | <分组时怎么搭，快的人给什么额外任务> |

## 收尾模板

```
"今天到这儿。走之前每个人写三行：
 一、你今天改变了什么判断；
 二、回去第一件要试的事；
 三、试的时候最可能卡在哪。
 写完不用交，拍张照发到群里。"
```
