# 课程物料包 · course-material-pack

> 讲师手册的验收标准只有一条：**一个没参与设计的讲师，拿着它能把这堂课上完。**
> 做不到这一点，写得再漂亮也只是课程说明书。

## 硬约束

1. **先锁三个参数再动手**：目标学员是谁、多长时间、结束时学员能做什么（**可衡量的动作，不是"了解"**）。三个参数不齐不得进入设计。**未满足本步退出条件，不得进入下一步。**
2. **每个核心模块必须有学员动手环节。** 纯讲授的模块直接打回重设计。
3. **案例必须是真实商业场景**，带公司、动作、数字、结果。**"假设你是某公司 CEO"这类虚构案例一律不许进物料。**
4. **提到的 AI 工具、模型版本、价格，必须联网现查。** 训练知识会过时，写进物料就是把讲师推到台上出错。
5. **物料按"拿来即用"标准交付**，不出"仅供参考"版本。做不完的部分明确标 `TODO` 并说清缺什么。

## 权限与数据边界

| 项 | 边界 |
|----|------|
| 读 | 本工作区 `memory/`、搭档提供的课程素材；联网公开信息 |
| 写 | 物料文件与本工作区 `memory/`；**不写入任何其他 Agent 的工作区** |
| 外发 | 无。不代为发送给学员、不上传到任何培训平台 |
| 敏感数据 | 客户公司的内部数据、学员个人信息，未经许可不写进物料；案例脱敏后使用 |
| 升权 | 不需要 `exec`、不需要 sudo、不安装任何包 |

## 何时使用 / 何时不用

| 场景 | 用不用 |
|------|--------|
| "帮我设计一门 AI 实战课" | ✅ 用 |
| "做一份讲师手册" | ✅ 用 |
| "这门课太理论了，改成实战的" | ✅ 用（从 Step 2 切入） |
| "设计一个苏格拉底追问环节" | ❌ → `socratic-training-design` |
| "把大纲做成 PPT" | ❌ → `deck-builder` |
| "这段文案太 AI 了" | ❌ → `human-writing` |
| "查一下这个行业的数据" | ❌ → `point-intel` |

**升级信号**：搭档要的其实是"这个主题我自己都还没吃透" → 先做知识梳理，别急着排课。
**降级信号**：只要一个 90 分钟的单点工作坊 → 走精简路径（Step 1 → 2 → 3 → 5），跳过学员手册和评估表。

## 输入输出契约

**输入**：课程主题 + 三个参数（学员画像 / 时长 / 可衡量的能力目标）+ （可选）已有大纲或素材
**输出**：一个物料包目录，含
`01-课程大纲.md` / `02-讲师手册.md` / `03-学员练习册.md` / `04-案例库.md` / `05-评估表.md`
**上游**：`oscar-research`、`point-intel` 的行业事实与案例素材
**下游**：`deck-builder`（出课件）、`mermaid-visual`（出框架图）、`human-writing`（物料过七遍）
**串联示例**：`point-intel`（查真实案例）→ `course-material-pack`（出物料）→ `socratic-training-design`（补追问链）→ `human-writing`（去 AI 腔）→ `deck-builder`（出课件）

## 流程

### Step 1 · 锁三个参数

**标准话术**（一次问完，不要一个个挤牙膏）：

> "开工前对三件事：**学员是谁**（创业者 / 高管 / 中层）、**多长**（半天 / 1 天 / 2 天）、**结束时他们能做什么**。第三件说具体动作，比如'能用 AI 拆一个自己业务的定价方案'，不是'掌握 AI 定价'。"

**退出条件**：三个参数都有具体答案，且第三项是可衡量的动作。**未满足本步退出条件，不得进入下一步。**
**常见失败**：抛出一串 ABCDEFG 选项让搭档挑，把设计工作反推给他。

### Step 2 · 排结构与时间

用体验式骨架，比例按时长缩放：

| 段落 | 占比 | 目标 | 形式 |
|------|------|------|------|
| 开场 · 摸底 | 10% | 让学员看见自己现在的水平 | 全员诊断题 |
| 核心 · 体验实战 | 70% | 场景 20% + 引导 30% + 动手 40% + 复盘 10% | 小组 + 个人 |
| 收尾 · 迁移 | 20% | 带走一份能落地的行动计划 | 个人 + 全员 |

每个核心模块写成四件事：真实场景 → 引导式思考 → 动手实战 → 复盘反馈。

**退出条件**：每个模块的分钟数加总等于总时长，且每个模块都有动手环节。
**常见失败**：时间加起来超出 20%，讲师现场只能砍掉最后的迁移环节，课就白上了。

### Step 3 · 写讲师手册（本技能最核心的一步）

每个模块必须写全五件事，模板见 `assets/facilitator-guide.md`：

1. **讲师话术** —— 写成能直接念出口的句子，不是"介绍本模块目标"
2. **诊断题或场景题** —— 带正确答案和常见错误答案的解读
3. **观察要点** —— 学员出现什么行为说明处在什么水平
4. **追问话术** —— 学员选了 A 怎么问，选了 B 怎么问
5. **应对预案** —— 冷场怎么办、有人抬杠怎么办、进度超时砍哪块

**退出条件**：随机抽三个模块，每个都能让一个没参与设计的讲师照着走完。
**常见失败**：手册写成大纲的展开版，讲师上台还要自己想怎么说。

### Step 4 · 出练习与案例

四类练习（模板见 `assets/exercise-set.md`）：个人反思题（暴露思维路径，**不打分**）、配对辩论题（抽签定立场）、小组实战题（有交付物）、迁移应用题（换个行业同构场景）。

案例库每条必须四段齐全：场景 → 问题 → AI 怎么用的 → 结果（带数字）。缺一段的案例不许进库。

**退出条件**：练习数 ≥ 模块数；案例四段齐全率 100%；每条案例可追溯到来源。
**常见失败**：练习题问"你觉得 AI 能怎么帮你"，学员答不出，环节死掉。好的练习题一定给具体场景和具体选项。

### Step 5 · 质量自检与交付

跑一遍自检闸门。工具与版本信息在交付前再核一次时间戳。

**退出条件**：自检闸门全过。

## 自检闸门

交付前逐条打勾，**有一条不过就回退到对应步骤**：

- [ ] 能力目标是可衡量的动作　→ 不过回 Step 1
- [ ] 各模块分钟数加总 = 总时长　→ 不过回 Step 2
- [ ] 每个核心模块都有学员动手环节　→ 不过回 Step 2
- [ ] 每个模块五件事齐全（话术 / 题目 / 观察 / 追问 / 预案）　→ 不过回 Step 3
- [ ] 案例全部真实且四段齐全　→ 不过回 Step 4
- [ ] 练习题带具体场景与选项，不是开放式空问　→ 不过回 Step 4
- [ ] 提到的工具与模型版本已联网核实并标注核实日期　→ 不过回 Step 5
- [ ] 物料里没有客户内部数据与学员个人信息　→ 不过，立即改并向搭档报告

## 量化验收指标

| 指标 | 门槛 |
|------|------|
| 讲师手册中可直接念的话术条数 | 每模块 ≥3 条 |
| 有动手环节的核心模块占比 | **100%** |
| 真实案例占比 | **100%**（虚构案例 0 条） |
| 案例四段齐全率 | **100%** |
| 练习题数 | ≥ 模块数 |
| 应对预案条数 | 每模块 ≥2 条（含超时砍哪块） |
| 时间分配误差 | **0 分钟** |
| 未核实的工具/版本表述 | **0** |
| 标 `TODO` 的部分 | 允许存在，但必须写清缺什么、谁来补 |

## 常见失败模式

| 失败 | 表现 | 怎么避免 |
|------|------|---------|
| 目标不可衡量 | "了解 / 掌握 / 熟悉 AI 营销" | Step 1 逼出具体动作 |
| 手册=大纲展开 | 只有"本模块讲什么"，没有怎么讲 | 五件事逐项写 |
| 虚构案例 | "假设你是某公司 CEO" | 真实案例是硬约束 |
| 时间不够 | 排了 8 小时的内容进 4 小时 | 分钟数必须加总核对 |
| 纯讲授 | 学员全程听，没动过手 | 每模块必有动手 |
| 空问练习 | "你觉得 AI 能怎么帮你" | 给场景 + 给选项 |
| 版本过期 | 写了半年前的模型名和价格 | 交付前现查并标日期 |
| 无预案 | 冷场、抬杠、超时全靠讲师临场 | 每模块 ≥2 条预案 |

## 降级与失败路径

**主题超出能力范围**：如实说"这个主题我需要先补材料"，用 `oscar-research` 或 `point-intel` 补完再排课。**不要用通用框架糊一门课出来** —— 学员是创业者，糊的东西他们一眼看得出来。

**没有真实案例**：先查（行业报道、财报、公开复盘、从业者访谈）。查不到就换一个有案例的场景，**不要编**。实在没有就把该模块改成"学员带自己的真实业务来做"，把案例的责任交回现场。

**时间不够做全套**：优先级是 **课程结构 + 讲师手册 > 练习册 > 案例库 > 评估表**。后面的标 `TODO` 并写清缺什么，不降低前面的标准。

**搭档催得急**：交精简路径的产物（大纲 + 讲师手册 + 3 个案例），明确说这是精简版、缺哪几件。**不要把半成品当成品交。**

## 执行留痕与记忆写回

**留痕**：物料包保留 `00-设计说明.md`，记录三个参数、结构比例的依据、每个案例的来源与核实日期。讲师上完课后可对着它复盘哪一段设计失效了。

**写回 `memory/YYYY-MM-DD.md`**：

1. 这次做的课是什么、给谁上、多长
2. 用了哪些真实案例、来源在哪
3. 搭档改了什么（**这条最值钱** —— 改动集中的地方就是下次设计的默认值）
4. 现场反馈（如果有）：哪个环节冷场、哪个环节超时

**沉淀进 `MEMORY.md`**：搭档的授课偏好（喜欢的节奏、常用的开场方式、绝不接受的形式），以及已验证有效的案例清单。案例复用是本技能最大的复利。
