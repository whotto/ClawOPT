# 团队健康诊断 · team-health-diagnosis

> 不是扫描文件吐报告，是**诊断根因、给出改进路径**。先说问题，再说解法。

## 硬约束

1. **只读。** 读被诊断 Agent 的文件，**绝不写入它们的工作区**。`Write` 只用于把报告写进本工作区。
2. **每个问题必配四要素**：问题 / 根因 / 解法 / 预期效果。只说问题不给解法是耍流氓。
3. **每个判断有数据。** "感觉不太行"不是诊断，"配置完成度 40%、缺 3 个核心技能、7 天无使用记录"才是。
4. **追问 2-3 层"为什么"。** 停在表面现象等于没诊断。
5. **数据缺失就标"数据缺失"**，不猜分、不脑补。
6. **未满足本步退出条件，不得进入下一步。**

## 权限与数据边界

| 项 | 边界 |
|----|------|
| 读 | 被诊断 Agent 工作区的 `AGENTS.md`/`SOUL.md`/`IDENTITY.md`/`skills/`；使用记录；输出样本 |
| **不读** | 被诊断 Agent 的 `MEMORY.md` 与 `USER.md` **正文**——那是别人的私密记忆。**只统计"存在与否、体积、是否为空模板"，不读内容** |
| 写 | 仅本工作区 `memory/diagnosis/`、`memory/baselines/` |
| 外发 | 无。诊断报告是 S2 内部级，**不进群聊** |
| 敏感数据 | 报告里引用输出样本时**脱敏**：去掉人名、客户名、具体金额 |
| 升权 | 不需要 `exec`、不联网（需外部基线时调 `oscar-research`/`point-intel`） |

> **为什么不读别人的 MEMORY.md**：那是 S1 私密数据。诊断"记忆层有没有在用"只需要看文件是否存在、体积多大、是不是还停在模板占位符——不需要读内容。这是本技能与"扫描一切"式工具的关键区别。

## 何时使用 / 何时不用

| 场景 | 用不用 |
|------|--------|
| "帮团队做个体检" | ✅ 全面体检 |
| "这个 Agent 最近不太对" | ✅ 定向诊断 |
| "快速看一眼有没有明显问题" | ✅ 轻量扫描 |
| "技能配置怎么样、哪些值得推广" | ❌ → `skill-assessment` |
| "出个周报" | ❌ → `progress-report` |
| "这个 Agent 说话开始像客服了" | ❌ → `culture-audit` |
| "要不要加一个新角色" | ❌ → 科学决策 `roi-deep-dive`（诊断结论可作输入） |

**三档深度**：

| 档位 | 覆盖 | 耗时 | 什么时候用 |
|------|------|------|-----------|
| 轻量扫描 | 五维打分，不追根因 | 5 分钟 | 定期巡检、心跳 |
| 定向诊断 | 1-3 个成员，全维度 + 根因 | 20 分钟 | "某个 Agent 不对劲" |
| 全面体检 | 全员 + 协作面 + 根因 + 改进路径 | 60 分钟+ | 季度、架构调整前 |

## 输入输出契约

**输入**：诊断范围（全团队 / 指定成员）+ 关注点（整体 / 某个方面）+ 深度档位
**输出**：`assets/health-report.md` 格式的报告。必含五维评分（带证据行）+ 问题四要素 + 优先级 + 亮点识别
**上游**：`point-intel`/`oscar-research` 提供外部基线；`progress-report` 提供变化趋势
**下游**：改进建议的执行 → CEO助理 `task-execution`；涉及资源分配的 → 科学决策 `roi-deep-dive`；发现技能问题 → `skill-assessment`；发现行为偏离 → `culture-audit`
**串联示例**：`team-health-diagnosis` →（发现技能缺口）→ `skill-assessment` →（改进执行）→ CEO助理

## 流程

### Step 1 · 确认范围

**中高自由度动作，必须确认**（轻量扫描和他说"直接做"时跳过）：

```
1. 复述请求："你要看 [全团队 / 某个成员] 的 [整体健康 / 某个方面]"
2. 提出方案：
   - 诊断类型：[全面体检 / 定向诊断 / 轻量扫描]
   - 覆盖范围：[列出将扫描的成员]
   - 预计深度：[快速概览 / 中等深度 / 深度拆解]
3. 询问："这个方向对吗？"
```

**退出条件**：他确认，或明说"直接做"。
**常见失败**：上来就开始扫文件。

### Step 2 · 建立假设

根据他的描述，**先形成 2-3 个可能的根因假设**，再去采数据验证/推翻。

> 例：他说"这个 Agent 最近老答非所问"
> 假设 A：技能 description 写得含糊，路由失准
> 假设 B：AGENTS.md 里的路由表和实际技能对不上（指向不存在的技能）
> 假设 C：上下文预算超了，关键规则被截断

**退出条件**：写下 2-3 条可证伪的假设。
**为什么必须**：假设驱动能让采数据有靶心。没有假设的扫描会变成"把所有文件读一遍然后不知道说什么"。

### Step 3 · 采集数据

| 数据源 | 采集方式 | 注意 |
|--------|---------|------|
| 配置文件 | 读 `AGENTS.md`/`SOUL.md`/`IDENTITY.md` 完整度 | 只读 |
| 技能文件 | `ls skills/` + 读每个 `SKILL.md` 的 frontmatter 与结构 | **重点查：路由表里声明的技能是否真实存在** |
| 记忆层 | **只看文件是否存在、体积、是否仍是模板占位** | **不读正文** |
| 使用记录 | 对话频率、使用深度、沉寂角色 | |
| 输出质量 | 抽样 **≥3 份**输出 | 引用时脱敏 |
| 协作记录 | 角色间转交、信息流转、边界重叠/真空 | |
| 外部基线 | 调 `point-intel` / `oscar-research` | 需要时才用 |

**退出条件**：≥3 个数据源已采，每个假设都有支持或推翻它的证据；采不到的显式标"数据缺失"。

### Step 4 · 五维评分（带证据行）

**每维 20 分，满分 100。每个扣分点必须写清扣在哪、依据是什么。**

| 维度 | 判据 |
|------|------|
| **配置完整度** | 五件套（AGENTS/SOUL/IDENTITY/USER/MEMORY）齐全且非模板占位；边界与红线显式写明；上下文预算未超 |
| **技能完备度** | 声明的技能是否都有实际 `SKILL.md`（**指向不存在的技能是 P0**）；每个技能是否有流程 + 退出条件 + 输出模板 + 质量标准 |
| **使用活跃度** | 近 7/30 天是否有实际会话；有没有"配了但从没用过"的沉寂角色 |
| **输出质量** | 抽样 3 份：结论先行否、有无来源标注、可否直接使用、有无 AI 味 |
| **协作效能** | 角色边界有无重叠或真空；转交时是否带上下文；跨角色请求是否闭环 |

**评分纪律**：

```
✅ "技能完备度 12/20。扣分依据：AGENTS.md 路由表声明 6 个技能，
    skills/ 下实际只有 4 个；oscar-research 与 point-intel 目录不存在（-6）；
    task-execution 的 SKILL.md 无退出条件（-2）。"

❌ "技能完备度一般，建议完善。"
```

**退出条件**：五维都有分数 + 证据行；数据缺失的维度标"数据缺失"而非给分。

### Step 5 · 多视角交叉验证

至少三个角度，防止单一数据源误判：

| 视角 | 核心问题 | 看什么 |
|------|---------|--------|
| **Ready 度** | 人到位了吗？技能配齐了吗？ | 配置完整度、技能覆盖度 |
| **资源风险** | 有人同时负责太多事吗？关键能力集中在一处吗？ | 任务分布、单点故障 |
| **执行可行性** | 改进路径清晰吗？有没有堵点？ | 依赖关系、优先级排序 |

**退出条件**：三个视角都过了一遍，结论互不矛盾（矛盾则回 Step 3 补数据）。

### Step 6 · 定位根因

**追问 2-3 层"为什么"**：

```
现象：这个 Agent 答非所问
 └ 为什么？→ 路由到了错误的技能
    └ 为什么？→ 两个技能的 description 都提到"分析"，语义重叠
       └ 为什么？→ description 写的是"能做什么"，没写"什么时候用/什么时候不用"
          ★ 根因：技能描述缺少排他性触发条件
```

**根因必须具体可操作**：不是"配置不好"，而是"SKILL.md 的 description 缺少'不要用于 X'的排他条款"。

**退出条件**：每个 P0/P1 问题都追到了可操作的根因。

### Step 7 · 输出（四要素 + 亮点）

**每个问题四要素缺一不可**：问题（具体发现了什么）/ 根因（为什么会这样）/ 解法（怎么改、改什么）/ 预期效果（改完会怎样）。

**优先级**：P0 = 影响正常工作；P1 = 明显拖累效率；P2 = 优化项。

**Step 7b · 识别亮点**（不只找问题）：哪个角色/技能做得好、是否值得推广、赋能方式（直接复制 / 适配复制 / 参考借鉴）。

**报告顺序：先说问题，再说解法。不美化，不隐瞒。**

**退出条件**：自检闸门全过。

## 自检闸门

- [ ] 全程**只读**被诊断工作区，未写入任何外部文件　→ 不过，立即报告并回滚
- [ ] 未读取他人 `MEMORY.md`/`USER.md` 正文　→ 不过，删除相关内容
- [ ] 数据源 ≥3 个　→ 不过回 Step 3
- [ ] 五维每个分数都有证据行　→ 不过回 Step 4
- [ ] 数据缺失的维度标注了"数据缺失"而非猜分　→ 不过回 Step 4
- [ ] 三视角交叉验证已做　→ 不过回 Step 5
- [ ] 每个 P0/P1 追问了 ≥2 层"为什么"　→ 不过回 Step 6
- [ ] 每个问题四要素齐全　→ 不过回 Step 7
- [ ] 有亮点识别（不只是问题清单）　→ 不过回 Step 7b
- [ ] 报告顺序是先问题后解法　→ 不过，重排
- [ ] 输出样本引用已脱敏　→ 不过，脱敏
- [ ] 全文 0 处"建议优化"这类空话　→ 不过，改写

## 常见失败模式

| 失败 | 表现 | 怎么避免 |
|------|------|---------|
| 上来就扫 | 没确认范围就读一堆文件 | Step 1 是硬门槛 |
| 无假设扫描 | 读完所有文件不知道说什么 | Step 2 先立假设 |
| 拍脑袋打分 | "配置完整度 15 分"但说不出扣在哪 | 证据行是硬要求 |
| 单源定论 | 只看配置文件就下结论 | ≥3 数据源 + 三视角 |
| 停在表面 | "这个 Agent 不好用" | 追问 ≥2 层为什么 |
| 只诊断不治疗 | 列了问题不给解法 | 四要素缺一不可 |
| 空话建议 | "建议优化配置" | 说"缺了 X，补法是 Y，预期 Z" |
| 只找问题 | 报告全是负面 | 亮点识别是必做项 |
| **越权写入** | 顺手把别人的配置改了 | **只读是红线** |
| **偷看记忆** | 读了别人的 MEMORY.md 正文 | 只统计不读正文 |
| 猜分 | 数据缺失也硬给个分数 | 标"数据缺失" |

## 降级与失败路径

| 情况 | 做法 |
|------|------|
| **拿不到使用记录** | 该维度标"数据缺失"，报告开头声明"本次五维仅 4 维有数据，总分不可与历史直接比较" |
| **被诊断 Agent 没有工作区** | 如实说"这个角色还没落地成工作区，无法诊断配置层"，把它列进"未落地"清单 |
| **数据互相矛盾** | 不选边。并列呈现，标"需人工确认"，并说清矛盾意味着什么 |
| **根因追不到** | 追到哪层说哪层，明确写"根因追到第 2 层，再往下需要 XX 数据，目前拿不到" |
| **时间不够** | 降档到轻量扫描，只出五维分 + P0 清单，明说"这次没做根因分析" |
| **发现是决策问题不是配置问题** | 停下来说："这不是配置能修的，是要不要保留这个角色的决策。要不要拉科学决策？" |
| **发现严重问题涉及面子** | 照说。`SOUL.md` 的"不护短"是硬约束——但**说完一定给解法** |

## 执行留痕与记忆写回

**留痕（可审计）**：报告保留 ① 扫描了哪些文件 ② 抽样了哪几份输出 ③ 每个扣分点的证据 ④ 数据缺失项。任何人可复核这次诊断。

**基线快照**：每次全面体检把五维分数存 `memory/baselines/YYYY-MM-DD.md`，供 `progress-report` 做趋势对比。

**写回 `memory/YYYY-MM-DD.md`**：诊断范围与类型 / 核心问题（P0-P2）/ 给出的建议 / 他接受或搁置了哪些 / 待跟进项。

**长期沉淀 `MEMORY.md`**：团队健康趋势（哪些维度在好转/恶化）、**他容易接受哪类建议、哪类会被搁置及原因**（这条直接决定你下次怎么排优先级）。

**技能记忆（L4）触发**：某类问题（如"路由表指向不存在的技能"）反复出现 ≥3 次 → 按 `reference/EVOLUTION.md` 沉淀成专门的快速检查技能候选。
