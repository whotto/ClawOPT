# 技能盘点与赋能 · skill-assessment

> 好的能力要流动。**谁强就赋能给谁，不让好经验烂在一个人身上。**

## 硬约束

1. **只读。** 绝不修改被评估的技能文件。改不改由搭档决定。
2. **按 House Spec 打分**，不凭印象。评分标准见 `_shared/SKILL-SPEC.md`。
3. **每个分数有证据行**（缺哪一段、哪一条不合规）。
4. **缺口要具体**：不是"能力不足"，而是"没有覆盖 XX 场景，用户说 YY 时无技能可路由"。
5. **未满足本步退出条件，不得进入下一步。**

## 权限与数据边界

| 项 | 边界 |
|----|------|
| 读 | 各 Agent 工作区的 `skills/**/SKILL.md`、`AGENTS.md` 的路由表 |
| **不读** | 技能里可能包含的业务数据文件；他人 `MEMORY.md`/`USER.md` 正文 |
| 写 | 仅本工作区 `memory/diagnosis/` |
| 外发 | 无。盘点结果是 S2 内部级 |
| 敏感数据 | 引用技能片段时**去掉其中的客户名、项目代号** |
| 升权 | 不需要 `exec`、不联网 |

## 何时使用 / 何时不用

| 场景 | 用不用 |
|------|--------|
| "技能配置怎么样" | ✅ |
| "我们缺什么技能" | ✅ |
| "这个技能写得行不行" | ✅ 单技能评估 |
| "哪个技能值得推广给别的角色" | ✅ 赋能评估 |
| "团队整体健康度" | ❌ → `team-health-diagnosis` |
| "这个 Agent 行为不对" | ❌ → `culture-audit` |
| "要不要装某个第三方技能" | ❌ → `reference/SECURITY.md` §三 准入流程 |

## 输入输出契约

**输入**：盘点范围（全团队 / 某角色 / 某技能）
**输出**：`assets/skill-matrix.md` —— 成熟度矩阵 + 缺口清单 + 重叠清单 + 赋能建议
**上游**：`team-health-diagnosis` 发现技能维度低分时转入
**下游**：缺口补齐 → CEO助理 `task-execution` 或 `reference/EVOLUTION.md` 的沉淀流程；赋能动作 → 搭档决定
**串联示例**：`team-health-diagnosis` →（技能维度 12/20）→ `skill-assessment` →（缺口清单）→ `task-execution`

## 流程

### Step 1 · 确认范围与口径

问一句：**"看全团队的能力覆盖，还是评某几个技能的质量？"** 两者的产出完全不同。

**退出条件**：范围明确（全团队覆盖 / 单技能质量 / 赋能评估）。

### Step 2 · 清点（先对账）

**第一件事是对账，不是打分**：

| 对账项 | 怎么查 | 严重度 |
|--------|--------|--------|
| 路由表声明的技能，`skills/` 下是否真实存在 | 比对 `AGENTS.md` 的 Skill 映射表 vs `ls skills/` | **不存在 = P0** |
| `SKILL.md` 的 `name` 是否与目录同名 | 读 frontmatter | 不一致 = 加载失败，P0 |
| 是否有孤儿技能（存在但无人路由） | 反向比对 | P1 |
| `_pending/` 里是否积压了候选 | `ls skills/_pending/` | >30 天 = P1 |

**退出条件**：对账表完成，P0 项已列出。
**为什么先对账**：路由指向不存在的技能是**最常见也最致命**的问题——它不报错，只是静默地什么都不做。

### Step 3 · 成熟度打分（每技能 10 项，各 1 分）

按 House Spec：

| # | 检查项 | 判据 |
|---|--------|------|
| 1 | frontmatter 六字段齐全 | name/description/license/compatibility/metadata/allowed-tools |
| 2 | `name` 合规且与目录同名 | 小写、无连续连字符、≤64 字符 |
| 3 | `description` 含"何时用 + 何时不用" | 有排他条款才不会误触发 |
| 4 | 有「权限与数据边界」段 | 最小权限声明 |
| 5 | 有「输入输出契约」段 | 能与其他技能串联 |
| 6 | **每步有可二值判定的退出条件** | 写死"未满足不得进入下一步" |
| 7 | 有「自检闸门」 | 且标明不过回哪一步 |
| 8 | 有「量化验收指标」 | 是数字不是形容词 |
| 9 | 有「常见失败模式」表 | ≥5 条 |
| 10 | 有「执行留痕与记忆写回」 | 可审计 + 可沉淀 |

**成熟度分级**：9-10 成熟 ｜ 6-8 可用 ｜ 3-5 骨架 ｜ 0-2 空壳

**退出条件**：每个技能有分数 + 缺项证据行。

### Step 4 · 覆盖度分析

**缺口**：把该角色的高频请求列出来，逐条问"这句话进来路由到哪个技能"。路由不到的就是缺口。

```
✅ "用户说'帮我把这份纪要转成待办'——没有技能能接，
    task-execution 兜底但没有专门流程。缺口：会议纪要转结构化待办。"

❌ "任务处理能力有待加强。"
```

**重叠**：两个技能的 `description` 语义重叠 → 路由会随机。必须指出并给出排他改法。

**退出条件**：缺口与重叠都用"具体请求语句"表述，不用抽象能力词。

### Step 5 · 赋能评估

发现好技能时评估能不能推广：

| 赋能方式 | 什么时候用 |
|---------|-----------|
| **直接复制** | 与角色无关的通用流程（如可信度标注、检索留痕） |
| **适配复制** | 骨架通用但话术/判据要改（如"退出条件"的写法） |
| **参考借鉴** | 只有思路可迁移，流程要重写 |

**退出条件**：每个高分技能都判定了是否值得推广及方式。

## 自检闸门

- [ ] 先做了对账（路由 vs 实际存在）　→ 不过回 Step 2
- [ ] P0 项（技能不存在 / name 不匹配）已单独前置　→ 不过回 Step 2
- [ ] 每个技能 10 项都有判定与证据　→ 不过回 Step 3
- [ ] 缺口用"具体请求语句"表述　→ 不过回 Step 4
- [ ] 重叠已指出并给了排他改法　→ 不过回 Step 4
- [ ] 高分技能已判定赋能方式　→ 不过回 Step 5
- [ ] 全程未修改任何被评估文件　→ 不过，立即报告
- [ ] 引用技能片段已脱敏　→ 不过，脱敏

## 量化验收指标

| 指标 | 门槛 |
|------|------|
| 对账覆盖率 | 100%（路由表每条都验过） |
| 每技能打分项 | 10/10 项都有判定 |
| 证据行覆盖率 | 100%（每个扣分都说清缺哪段） |
| 缺口表述具体度 | 100% 用具体请求语句，0 抽象能力词 |
| 赋能判定覆盖率 | 100%（每个 ≥9 分技能都判过） |
| 修改被评估文件次数 | **0** |

## 常见失败模式

| 失败 | 表现 | 怎么避免 |
|------|------|---------|
| 跳过对账 | 直接打分，没发现有技能根本不存在 | 对账是 Step 2，先于打分 |
| 抽象缺口 | "调研能力有待加强" | 用具体请求语句 |
| 忽略重叠 | 只看有没有，不看会不会撞 | 重叠是必查项 |
| 只评不推 | 发现好技能但不提赋能 | Step 5 是必做 |
| 凭印象打分 | 没读全文就给分 | 每项要有证据行 |
| 越权修改 | 顺手把技能改了 | 只读是红线 |
| 忽略 `_pending/` | 候选积压没人管 | 对账时一并查 |

## 降级与失败路径

| 情况 | 做法 |
|------|------|
| **技能太多（>30 个）** | 先只做对账 + P0 清单，打分分批做。**对账永远优先于打分** |
| **技能文件读不到** | 标"无法访问"，不猜内容 |
| **缺口明显但不知道该配什么技能** | 如实说"这里有缺口，但我不确定最佳流程是什么"，建议用 `reference/EVOLUTION.md` 的沉淀路径让它从实战中长出来 |
| **两个技能重叠但都在用** | 不擅自建议合并。列出重叠点 + 两种改法（改 description 排他 / 合并），让搭档选 |
| **发现是角色划分问题** | 说清楚"这不是技能缺口，是两个角色的职责边界没划清"，转 `team-health-diagnosis` 的协作效能维度 |

## 执行留痕与记忆写回

**留痕**：矩阵保留每个技能的 10 项判定与证据，可复核。

**写回 `memory/YYYY-MM-DD.md`**：盘点范围 / P0 对账问题 / 成熟度分布 / 缺口清单 / 赋能建议 / 他采纳了哪些。

**长期沉淀 `MEMORY.md`**：技能成熟度趋势、**反复出现的技能缺陷类型**（如"大家都不写退出条件"→ 说明 House Spec 需要更醒目地传达）。

**技能记忆（L4）触发**：若某个赋能动作（把 A 的做法适配给 B）被验证有效，把"适配方法"本身沉淀成候选技能。
