# 进展报告 · progress-report

> 不只是"出了什么"，还有"**比上次好了多少**"。
> **迭代速度是团队健康的核心指标——不进步就是在退步。**

## 硬约束

1. **必须有对比基线。** 没有基线的报告只是流水账。找不到基线就**明说"这是第一份，作为基线"**。
2. **数据缺失标数据缺失。** 不用"预计""大约""应该有"糊过去。
3. **低自由度技能**：需求明确（"出个周报"）时**不确认，直接做**。
4. **变化优先于存量。** 报告的主体是 Δ，不是清单。
5. **未满足本步退出条件，不得进入下一步。**

## 权限与数据边界

| 项 | 边界 |
|----|------|
| 读 | 各工作区的 `memory/YYYY-MM-DD.md`、`memory/baselines/`、`memory/diagnosis/`、automations 运行记录 |
| **不读** | 他人 `MEMORY.md`/`USER.md` 正文 |
| 写 | 仅本工作区 `memory/reports/` |
| 外发 | **报告可能被搭档转发给团队**——因此默认按 **S2 内部级**写，不含私人信息、不含未脱敏的输出样本 |
| 敏感数据 | 涉及具体项目名/客户名时用代号，或先问搭档能不能写 |
| 升权 | 不需要 `exec`、不联网 |

## 何时使用 / 何时不用

| 场景 | 用不用 |
|------|--------|
| "出个周报" | ✅ |
| "最近有什么变化" | ✅ |
| "这个月团队进展怎么样" | ✅ 自定义时间段 |
| "团队健康度怎么样" | ❌ → `team-health-diagnosis` |
| "哪些技能该改" | ❌ → `skill-assessment` |
| "某个 Agent 行为不对" | ❌ → `culture-audit` |

**三种时间粒度**：

| 粒度 | 基线 | 重点 |
|------|------|------|
| 日报 | 昨天 | 完成项 + 未闭环项 |
| 周报 | 上周 | 变化 + 迭代速度 + 卡点 |
| 自定义 | 用户指定的起点 | 趋势 |

## 输入输出契约

**输入**：时间粒度（日/周/自定义）+ （可选）关注重点
**输出**：`assets/progress-report.md` —— 必含基线对比、Δ 变化、迭代速度评价、未闭环项、下期看点
**上游**：`team-health-diagnosis` 的 `memory/baselines/` 五维快照；各角色的 `memory/YYYY-MM-DD.md`
**下游**：报告中的卡点 → `team-health-diagnosis` 做定向诊断；未闭环项 → CEO助理 `task-execution`
**串联示例**：`team-health-diagnosis`（存基线）→ `progress-report`（对比）→（发现恶化）→ `team-health-diagnosis`（定向诊断）

## 流程

### Step 1 · 定基线

**先找上一份**：`memory/reports/` 里最近的同粒度报告，或 `memory/baselines/` 的五维快照。

| 情况 | 做法 |
|------|------|
| 找到基线 | 记下基线日期与关键数值 |
| 找不到 | **明说"这是第一份 XX 报告，作为基线"**，本期不做 Δ 分析 |
| 基线太旧（周报但上一份是一个月前） | 明说时间跨度不可比，改按实际跨度出 |

**退出条件**：基线已确定，或已显式声明"无基线"。

### Step 2 · 采集变化

按维度采，**每条都要能回答"从什么变成了什么"**：

| 维度 | 采什么 |
|------|--------|
| 产出 | 完成了哪些任务/调研/诊断/决策（数量 + 代表性的 2-3 个） |
| 配置 | 哪些文件改了、新增或废弃了哪些技能 |
| 技能库 | `_pending/` 新增与消化、`_archived/` 新增 |
| 健康度 | 五维分数 Δ（来自 baselines） |
| 未闭环 | 上期说要做但没做完的 |
| 卡点 | 反复出现的阻塞 |

**退出条件**：每个维度都有数据或标"数据缺失"。

### Step 3 · 评价迭代速度

**这是本技能与普通流水账的分界线。**

| 判据 | 说明 |
|------|------|
| 上期问题的解决率 | 上期列的 P0/P1 这期改了几个 |
| 新增能力 | 新技能、新流程、新沉淀 |
| 重复问题 | 同一个问题连续 ≥2 期出现 = **恶化信号** |
| 未闭环存量 | 是在减少还是在累积 |

**评价语必须带依据**：

```
✅ "迭代速度：偏慢。上期 3 个 P0 只解决 1 个；未闭环项从 4 个涨到 7 个；
    '路由表指向不存在的技能'连续第 3 期出现。"

❌ "迭代速度良好，团队保持了不错的进展。"
```

**退出条件**：速度评价有 ≥2 条量化依据。

### Step 4 · 输出

用 `assets/progress-report.md`。**结构顺序固定**：一页纸速览 → Δ 变化 → 迭代速度 → 未闭环 → 下期看点。

**退出条件**：自检闸门全过。

## 自检闸门

- [ ] 基线已明确，或已声明"这是第一份"　→ 不过回 Step 1
- [ ] 每条变化都能回答"从什么变成了什么"　→ 不过回 Step 2
- [ ] 数据缺失项已标注，无"预计/大约"糊弄　→ 不过回 Step 2
- [ ] 迭代速度评价有 ≥2 条量化依据　→ 不过回 Step 3
- [ ] 连续出现 ≥2 期的重复问题已单独标红　→ 不过回 Step 3
- [ ] 未闭环项有存量对比（涨了还是降了）　→ 不过回 Step 2
- [ ] 报告按 S2 内部级写（无私人信息、样本已脱敏）　→ 不过，脱敏
- [ ] 全文 0 处"进展良好""稳步推进"这类无依据评价　→ 不过，改写

## 量化验收指标

| 指标 | 门槛 |
|------|------|
| 基线明确率 | 100%（有基线或显式声明无基线） |
| 变化项带 Δ 的比例 | 100% |
| 迭代速度依据条数 | ≥2 条量化 |
| "预计/大约/应该"出现次数 | **0** |
| 无依据评价语出现次数 | **0** |
| 重复问题标注率 | 100%（连续 ≥2 期的必须标） |
| 日报耗时 | ≤3 分钟 |
| 周报耗时 | ≤15 分钟 |

## 常见失败模式

| 失败 | 表现 | 怎么避免 |
|------|------|---------|
| 流水账 | 只列做了什么，没有对比 | 基线是硬门槛 |
| 无依据评价 | "进展良好""稳步推进" | 评价必带 ≥2 条量化依据 |
| 糊弄缺失 | "预计完成 3 项" | 标"数据缺失" |
| 漏重复问题 | 同一问题第 3 次出现却没标 | 重复 ≥2 期必须标红 |
| 只看产出不看存量 | 未闭环项一直涨却没提 | 未闭环必须给存量对比 |
| 报喜不报忧 | 恶化维度轻描淡写 | `SOUL.md` 的"不粉饰"是硬约束 |
| 越粒度 | 让出日报却写了周报的量 | 粒度决定篇幅 |
| 泄密 | 报告里带了客户名和具体金额 | 默认 S2 内部级 |

## 降级与失败路径

| 情况 | 做法 |
|------|------|
| **找不到任何基线** | 出一份"基线版"报告，只有现状快照，明确写"下期开始做 Δ 分析" |
| **数据源缺失（某角色没写 memory）** | 该角色一栏标"无记录"，并在报告里指出"X 角色近 N 天无记录"——**这本身就是一条重要发现** |
| **周期内确实没什么变化** | 如实写"本周无实质变化"，并列出未闭环存量。**不要为了填满报告而注水** |
| **变化太多写不完** | 只写 Top 5 变化 + 完整清单放附录，主体保持可读 |
| **发现严重恶化** | 报告照出，同时**主动提议**："健康度掉了 12 分，要不要做个定向诊断？" |
| **搭档要求把报告发给团队** | 先做一次脱敏检查（人名/客户名/金额/内部项目代号），确认后由**他**发，不由你发 |

## 执行留痕与记忆写回

**留痕**：报告保存到 `memory/reports/YYYY-MM-DD-<粒度>.md`，本身就是下一期的基线。

**写回 `memory/YYYY-MM-DD.md`**：出了哪期报告、核心结论一句、他关注了哪一条。

**长期沉淀 `MEMORY.md`**：**迭代速度趋势**（这是团队健康的核心指标）、反复出现的卡点类型、他最关心哪个维度（下次把它前置）。

**技能记忆（L4）触发**：若某类变化的采集方式（如"从 automations 运行记录反推实际活跃度"）被验证有效，沉淀成候选。
